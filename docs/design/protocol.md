# node ↔ Hub 协议

- 状态：草案
- 阶段：P0 设计；M1 实现主体，后续阶段增加消息类型（见第 13 节）
- 相关：ADR [0003](../adr/0003-api-and-protocols.md)、[auth.md](auth.md)、[changes.md](changes.md)、[api-resources.md](api-resources.md)

## 1. 范围与目标

本文定义 nett-node 与 Hub 之间的控制协议：连接建立、加密与认证、消息格式、期望状态下发、状态与指标上报、任务执行、断线重连和版本兼容。组网数据面（节点之间的流量）不在本文范围，见 `mesh.md`。

目标：

| 目标 | 含义 |
|---|---|
| 端到端安全 | 即使 TLS 在 Edge 终止，Edge 也无法读取或篡改消息 |
| 离线可用 | Hub 不在线时 node 照常工作；恢复后自动补齐状态和数据 |
| 资源占用低 | 单条长连接；消息紧凑；所有缓冲区有上限 |
| 可演进 | 相邻版本的 node 与 Hub 能够互通；新增能力不破坏旧版本 |

## 2. 分层

```
┌─ 消息：Protobuf Envelope（第 4、5 节）
├─ Noise 通道：Noise_IK_25519_ChaChaPoly_BLAKE2s（第 3 节）
├─ WebSocket：二进制帧；一个 WebSocket 消息承载一个 Noise 消息
└─ TLS：wss://，可以由 Edge 终止
```

- WebSocket 路径：`/node/v1/connect`。它不属于对外 REST API，不出现在 OpenAPI 文档中；
- 选择 WebSocket over TLS（443）而不是自定义端口，是为了穿过只放行 HTTPS 的网络，并与网站共用入口。

## 3. 加密通道与认证

### 3.1 密钥

| 密钥 | 类型 | 说明 |
|---|---|---|
| Hub 身份密钥 | X25519 静态密钥 | 公钥在入网时固定到节点（完整公钥包含在入网 token 中，IK 握手需要它） |
| 节点身份密钥 | X25519 静态密钥 | 入网时在节点本地生成，私钥不离开节点；Hub 保存公钥与节点 ID 的对应关系 |

Noise 的静态密钥直接作为身份密钥，不再另设签名密钥：通道本身已提供双向认证，需要独立验证的产物（节点策略、信任锚）由用户的 passkey 或恢复密钥签名（见 `auth.md`）。

### 3.2 握手（IK 模式，1 个往返）

```
node                                                     Hub
 │ 消息 1：e, es, s, ss + 加密载荷 Hello ───────────────────►│
 │                                                         │ 解出节点静态公钥 → 查找节点
 │                                                         │（入网时：校验 Hello 中的准入证明）
 │◄─────────────────── 消息 2：e, ee, se + 加密载荷 Welcome │
 │ 之后双方使用传输密钥收发消息
```

- Prologue：`nett-control/1`，防止与其他协议混用；
- 节点的静态公钥在消息 1 中加密传输，外部观察者无法得知是哪个节点在连接；
- Hub 拒绝未知或已吊销的节点公钥；拒绝时返回明确的错误码后关闭连接（见第 4.3 节）；
- 重新加密：每传输 2^20 条消息或每 24 小时执行一次 Noise rekey。

### 3.3 Hello 与 Welcome

| Hello（node → Hub） | 说明 |
|---|---|
| `protocol_versions` | 支持的协议版本范围 |
| `node_version` | nett 版本 |
| `node_id` | 节点 ID；入网时使用 token 中预先分配的 ID |
| `admission_proof` | 仅入网时携带：入网私钥对 `{节点 ID, 身份公钥, 组网公钥}` 的签名（`auth.md` 第 8.2 节） |
| `boot_id` | 本次进程启动的随机 ID，用于识别重启 |
| `applied_generation` | 本地已应用的期望状态代数（第 6 节） |
| `capabilities` | 可选功能标志（第 10 节） |

| Welcome（Hub → node） | 说明 |
|---|---|
| `protocol_version` | 选定的协议版本 |
| `hub_version` | Hub 版本 |
| `session_id` | 本次会话 ID |
| `server_time` | 服务器时间，用于时钟校准 |
| `keepalive_secs` | 心跳间隔 |
| `enrollment` | 仅入网时返回：信任锚清单、初始节点策略（见 `auth.md` 第 8 节） |

## 4. 消息格式

### 4.1 Envelope

```protobuf
message Envelope {
  uint64 id = 1;                 // 每个方向单调递增
  uint64 reply_to = 2;           // 应答时填写对方消息的 id
  google.protobuf.Timestamp sent_at = 3;
  oneof body {
    // 第 5 节列出的消息类型
  }
}
```

- 单条 Envelope 编码后不超过 60 KiB（Noise 单条消息上限为 65535 字节）；
- 超过上限的内容（如完整期望状态、补传的指标）使用分片：`Chunk { stream_id, seq, last, data }`，接收方按 `stream_id` 重组，每个流的总大小有上限。

### 4.2 包名与演进

- 包名 `nett.v1`；字段编号不复用，删除的字段使用 `reserved`；枚举的 0 值为 `*_UNSPECIFIED`；
- 不认识的 `oneof` 分支或字段：接收方忽略并记录调试日志，不断开连接。

### 4.3 错误

```protobuf
message Error {
  ErrorCode code = 1;   // 例如 NODE_REVOKED、UPGRADE_REQUIRED、INVALID_MESSAGE、RATE_LIMITED
  string message = 2;
  uint64 related_id = 3;
}
```

致命错误（如节点已吊销）发送后关闭连接；非致命错误只针对相关消息。

## 5. 消息类型

| 类别 | 方向 | 消息 | 用途 |
|---|---|---|---|
| 会话 | 双向 | `Ping` / `Pong` | 保活、往返时间、时钟偏差 |
| | 双向 | `Goodbye` | 主动关闭，附原因（升级、重启、关机） |
| | node → Hub | `Leave` | 节点自行退出（`nett leave`）；Hub 将节点标记为 `removed`，属于降低权限，不需要签名 |
| | 双向 | `Error` | 见 4.3 |
| 期望状态 | Hub → node | `DesiredState` | 期望状态快照或增量（第 6 节） |
| | node → Hub | `StateAck` | 应用结果，按分区报告 |
| 清单与状态 | node → Hub | `Inventory` | 平台、能力、地址、服务与端口；连接时发送完整版本，之后发送变化 |
| | node → Hub | `ModuleStatus` | 各模块状态与条件 |
| 指标 | node → Hub | `MetricsBatch` | 按分钟聚合的指标，包括补传数据（第 7 节） |
| | Hub → node | `LiveStart` / `LiveStop` | 开始、停止秒级实时采集（带有效期） |
| | node → Hub | `LiveSamples` | 实时数据 |
| 事件 | node → Hub | `NodeEvent` | 节点侧发生的事件：容器 OOM、重启、策略被拒绝、升级结果等 |
| 任务 | Hub → node | `Task` | 变更集步骤在节点上的执行请求（第 8 节） |
| | node → Hub | `TaskUpdate` | 接受、执行中、成功、失败，以及结果 |
| 备份 | node → Hub | `BackupFetch` | 存放备份的节点定时拉取最新的加密备份（Hub 从不主动连接节点） |
| | Hub → node | `BackupChunk` | 加密备份的分片；拉取是否按时完成作为一项心跳检查 |
| 组网（M2） | Hub → node | `DesiredState` 中的组网分区 | 地址、对端公钥及准入材料、候选路径、中继名单 |
| | node → Hub | `LinkReport` | 链路的当前路径、传输方式与质量 |
| 日志（M3） | Hub → node | `LogsRequest` | 读取容器最近的日志（只读，有大小上限） |
| | node → Hub | `LogsChunk` | 日志内容 |

## 6. 期望状态

### 6.1 分区与代数

期望状态按分区组织，每个分区独立版本化：

| 分区 | 内容 | 阶段 |
|---|---|---|
| `trust` | 信任锚清单（带签名） | M1 |
| `policy` | 节点策略（提升权限时带签名） | M1 |
| `hub_endpoints` | Hub 的端点列表 | M1 |
| `metrics` | 采集配置：间隔、启用的采集项 | M1 |
| `heartbeats` | 本节点上需要观察的心跳 | M1 |
| `release` | 目标版本与发布包地址；节点用编译进 `nett` 的项目公钥验证发布包，只自动接受更高的版本（`auth.md` 第 12.3 节）。这是升级的唯一通路 | M1 |
| `mesh` | 组网拓扑与准入材料。成员、宣告网段、访问规则集都是签名产物，节点独立验证（`mesh.md` 第 4.1 节） | M2 |
| `stacks` | 部署定义；敏感环境变量为用节点公钥加密的密文 | M3 |
| `ingress` | 路由与 Edge 配置 | M3 |

- 每个节点有一个单调递增的**代数**（generation），任一分区变化都会使代数加一；
- `DesiredState` 携带 `generation`、`base_generation` 和若干分区：`base_generation` 为空时是完整快照，否则是相对该代数的增量；
- 连接建立时，若节点的 `applied_generation` 与当前代数相差太多，或 Hub 不再保存对应的增量，Hub 发送完整快照。

### 6.2 应用与确认

- node 校验每个分区：带签名的分区先验签（见 `auth.md` 第 11 节），失败则拒绝该分区；与当前已生效版本完全相同的签名产物（例如完整快照中重发的策略）视为幂等，直接确认；
- 校验通过后写入本地 State Store，再交给对应模块调和；
- `StateAck` 报告每个分区的结果：`applied` / `rejected`（附原因） / `pending`（模块仍在调和）；
- 节点重启时先应用本地保存的期望状态，再连接 Hub。

### 6.3 Hub 离线时

- 节点按本地期望状态继续运行；
- 模块的调和、组网的选路与切换都不依赖 Hub；
- 需要 Hub 参与的操作（新任务、配置变更）在恢复连接后继续。

## 7. 指标上报

- 采集默认每 10 秒一次，在节点上聚合为每分钟一个点，每分钟批量上报；
- **编码**：每个批次先给出指标序列字典（序列名与维度 → 序号），之后的数据点只引用序号；时间戳用差值编码；
- **本地缓冲**：未确认的批次存入节点本地的环形缓冲文件，上限为 6 小时数据或 4 MiB，取较小者；超出时丢弃最旧的数据，并在恢复连接后以事件说明丢失的时间段；
- **补传**：恢复连接后，节点以受限的速率补传缓冲中的数据，Hub 按批次 ID 去重；
- **实时模式**：收到 `LiveStart` 后按秒采集并直接发送，不进入缓冲；有效期到期或收到 `LiveStop` 后停止。

## 8. 任务

变更集中需要节点执行的步骤，以任务的形式下发：

```protobuf
message Task {
  string task_id = 1;        // 全局唯一
  string change_id = 2;
  uint32 step = 3;
  string action_type = 4;
  bytes payload = 5;         // 按动作类型定义的 Protobuf 消息
  google.protobuf.Timestamp deadline = 6;
}
```

- **只执行动作目录中已定义的动作类型**；未知类型直接返回失败；
- 部署类任务在执行前，由节点按本机的部署档位检查（`changes.md` 第 7.1 节），超出档位直接拒绝，不依赖 Hub 的判断；
- **恰好执行一次**：节点在本地记录已接受和已完成的 `task_id`（保留 7 天，最多 1000 条，超出时删除最旧的记录）；重复收到相同任务时返回已有结果，不重复执行；
- 同一时间进行中的任务数量有上限；超出时返回 `RATE_LIMITED`；
- 超过 `deadline` 尚未开始的任务不再执行，返回超时；
- 执行结果通过 `TaskUpdate` 上报；连接中断时结果保存在本地，恢复后补报。

## 9. 保活与重连

| 项 | 规则 |
|---|---|
| 保活 | 每 25 秒一次 `Ping`（也用于避免中间代理因空闲断开连接）；连续 3 次无应答视为断开 |
| 重连 | 指数退避，起始 1 秒，上限 60 秒，带随机抖动 |
| 端点选择 | 按 Hub 下发的端点列表并发尝试，选择最先完成握手的端点；连接到备用端点后，定期尝试优先端点 |
| 会话 | 不做会话恢复；每次重连重新握手，通过 `applied_generation` 和未确认的批次、任务结果补齐状态 |
| 时钟 | 根据 `Pong` 中的服务器时间估算偏差；偏差超过 30 秒时上报事件并告警 |

## 10. 版本兼容

- 协议版本采用"主版本.次版本"：主版本不同则不兼容；次版本只做增量修改；
- Hub 至少支持当前和上一个次版本的节点；节点同样能够连接上一个次版本的 Hub；
- **可选功能**通过 `capabilities` 标志协商，例如 `chunked_state`、`live_metrics`、`logs`；双方只使用都支持的功能；
- 节点版本过旧、无法兼容时，Hub 返回 `UPGRADE_REQUIRED`，但仍允许其进入**仅升级模式**：只接收 `release` 分区和升级任务，以便完成自动升级。

## 11. 安全

| 威胁 | 措施 |
|---|---|
| Edge 或中间网络窃听、篡改 | Noise 端到端加密与认证 |
| 冒充 Hub | 节点固定 Hub 公钥；握手失败即断开 |
| 冒充节点 | Hub 只接受已登记的节点公钥；入网 token 一次性有效；准入证明由浏览器生成的入网私钥签名，Hub 无法替换节点的公钥 |
| Hub 被攻破后加入组网成员 | 成员只为能验证准入材料的对端配置 WireGuard（ADR 0014） |
| Hub 被攻破后提升节点权限 | 提升权限的分区必须带用户签名，节点独立验签 |
| 重放 | Noise 传输层自带计数器；期望状态代数与策略版本只增不减；任务按 `task_id` 去重 |
| 资源耗尽 | 消息大小、分片总量、进行中的任务、补传速率都有上限；Hub 对每个节点限流 |
| 恶意载荷 | 所有消息在边界处校验；节点只执行已知的动作类型 |

## 12. 资源预算

| 项 | node 侧上限 |
|---|---|
| 单条消息 | 60 KiB |
| 分片重组 | 单个流 8 MiB，写入磁盘上的临时文件，内存中只保留当前分片；同时进行的流 2 个 |
| 指标缓冲 | 6 小时或 4 MiB（磁盘），内存中只保留当前批次 |
| 已完成任务记录 | 7 天，最多 1000 条 |

M1 不使用压缩；如果补传或快照的体积成为问题，再以可选功能标志的方式加入按消息压缩。
