# 组网

- 状态：草案
- 阶段：P0 设计；M2 实现第一版，M5 增强（见第 18 节）
- 相关：ADR [0007](../adr/0007-own-mesh-wireguard-session-path-layer.md)、[0008](../adr/0008-mobile-dual-path.md)、[0011](../adr/0011-nett-relay.md)；[protocol.md](protocol.md)、[auth.md](auth.md)

## 1. 目标

节点之间有多条候选路径和多种传输方式；持续测量，自动选择最优路径；路径抖动、中断或节点离线时在几秒内切换，**进行中的连接不中断**；没有单点；Hub 离线不影响组网。

不在本期范围：每条连接独立选路（同一对节点的所有流量共用一条路径）；不同站点之间网段重叠的自动处理；Windows 平台。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 成员 | 加入组网的节点或设备 |
| 连接（link） | 一对成员之间的 WireGuard 会话 |
| 候选路径 | 一条连接可能使用的路径：局域网直连、公网直连、经中继、多跳接力 |
| 传输 | 承载 WireGuard 数据包的方式：UDP、TLS（WebSocket）、后期的 QUIC |
| `public` / `dial-only` | 能否被外部连入（见 architecture.md 第 6.5 节） |
| 中继 | 运行 nett-relay、为其他成员转发密文的 `public` 节点 |
| 智能入口 | 把整个局域网段接入组网的节点 |
| 移动网关 | 接受设备连接、把设备流量送入组网的节点 |

## 3. 地址规划

| 地址 | 规则 |
|---|---|
| IPv4 组网网段 | 默认 `100.88.0.0/16`，在 Hub 初始化时可修改；避开部分云厂商在 `100.100.0.0/16` 上提供的内部服务 |
| IPv6 组网网段 | Hub 初始化时随机生成一个 ULA `/48` |
| 成员地址 | 每个成员一个 IPv4 和一个 IPv6 地址，由 Hub 分配，终身不变；成员移除后地址冻结 90 天再回收 |
| 局域网网段 | 由智能入口宣告（第 10 节） |

Hub 在分配和宣告网段时检测冲突：组网网段与任何成员的局域网网段重叠、两个站点宣告的网段重叠，都会被拒绝并提示。

## 4. 会话层

- 每个节点一个 WireGuard 接口 `nett0`，监听一个 UDP 端口（默认 `41820`，可配置）；
- 对端：其他节点和设备。每个对端的 `AllowedIPs` 为其组网地址，加上它宣告的局域网网段；
- **WireGuard 私钥在本机生成，不离开节点**；公钥经 Hub 分发（期望状态的 `mesh` 分区）；
- Linux 使用内核 WireGuard，通过 netlink 配置；无内核模块的平台（Synology DSM、macOS、旧内核）使用 Rust 用户态实现与 TUN 设备；
- `dial-only` 成员对每个对端设置 25 秒的持久保活，维持 NAT 映射。

**切换路径 = 修改对端的 endpoint**。WireGuard 会话、密钥和上层的 TCP 连接都不受影响。

## 5. 中继

### 5.1 转发模型

中继不参与 WireGuard 会话，只按**端口分配**转发密文（与 TURN 类似）：

```
A 的 WireGuard ──► R:pA ──(nett-relay 转发)──► B 的 WireGuard
A 的 WireGuard ◄── R:pB ◄─(nett-relay 转发)─── B 的 WireGuard
```

- 一条经 R 的连接（A、B）占用 R 上的两个端口：`pA` 给 A 发送使用，`pB` 给 B 发送使用；
- A 把 B 的 endpoint 设为 `R:pA`，B 把 A 的 endpoint 设为 `R:pB`；
- R 记录两端的实际地址，把一端发来的数据包原样转给另一端；
- **多跳**：R1 不直接转给 B，而是转给 R2 上为这条连接分配的端口。

### 5.2 分配与授权

- 端口分配由 Hub 计算，经期望状态下发给中继所在节点；该节点的 nett-node 通过本地接口通知 nett-relay；
- nett-relay 只转发已分配端口上的流量；
- **地址绑定**：端点的实际地址只在收到**通过校验的 WireGuard 握手消息**时更新。握手消息中的 `mac1` 可以用公开的对端公钥校验，中继不需要任何私钥，也就无法被伪造的数据包劫持绑定；
- 每个中继有流量和带宽上限（由用户在节点上配置）；超过上限时，Hub 不再为它分配新的连接。

### 5.3 TLS 传输

当 UDP 不可用时：

```
A 的 WireGuard ─► 127.0.0.1:x（nett-node 本地适配器）─► WebSocket/TLS 443 ─► R 的 nett-relay ─► B
```

- nett-node 在本机回环地址上开一个 UDP 端口作为 WireGuard 的 endpoint，把收到的数据包按长度前缀写入 WebSocket 连接，反方向同理；
- 入口节点上，WebSocket 连接经 Edge 按域名转交给 nett-relay；
- 对方是 `public` 节点时，"直连的 TLS 传输"即连接到对方节点上的 nett-relay，由它交给本机的 WireGuard；
- TLS 传输中，WireGuard 承载的 TCP 在丢包时性能会下降（TCP 套 TCP），因此只在 UDP 不可用时使用。

## 6. 候选路径

Hub 为每一对成员计算候选路径列表，经 `mesh` 分区下发；成员在本地测量并选择。

| 候选路径 | 生成条件 |
|---|---|
| 局域网直连 | 双方上报的局域网地址处于同一网段，且探测确认可达 |
| 公网直连 | 至少一方为 `public` |
| 经中继 | 选取若干中继：优先地理和线路上位于两端之间的中继，结合线路质量矩阵 |
| 多跳接力（M5） | 单跳中继质量不佳，而两段接力明显更优 |
| 打洞直连（M5） | 双方都为 `dial-only` |

每种路径还可以与传输方式组合（UDP、TLS）。候选数量有上限（默认每对成员 6 条）。

**活跃连接**（最近 10 分钟有流量）完整测量；**空闲连接**只做低频测量，第一次有流量时立即按最优候选建立。

## 7. 测量

| 测量 | 方式 | 频率 |
|---|---|---|
| 当前路径 | 在隧道内发送探测（到对端组网地址），测往返时间和丢包 | 活跃连接每 2 秒 |
| 候选路径 | 隧道外的探测包，按路径分段测量：成员 → 中继、中继 → 成员、成员 → `public` 成员；经中继的路径由各段组合估算 | 活跃连接每 15 秒；空闲连接每 5 分钟 |
| 线路质量矩阵 | 汇总各段测量，上报 Hub | 每分钟 |

- 指标：往返时间（指数滑动平均）、丢包率（滑动窗口）、抖动；
- 探测包带认证：成员之间用双方 WireGuard 密钥派生的密钥计算校验码；发往中继的探测使用分配时下发的令牌；
- 应答方：`public` 节点由 nett-relay 应答；局域网和隧道内的探测由 nett-node 在**局域网地址和组网地址**上应答（不监听公网地址）；
- 探测流量有预算：每对活跃连接不超过约 1 KiB/s。

## 8. 选路与切换

### 8.1 评分

```
得分 = 往返时间 + 丢包惩罚 + 抖动惩罚 + 路径类型偏好 + 传输惩罚 + 中继成本
```

- 路径类型偏好：局域网 < 公网直连 < 经中继 < 多跳；
- 传输惩罚：TLS 高于 UDP；
- 中继成本：中继接近流量上限时提高；
- 支持策略覆盖（`links` 的 `spec.policy`）：优先直连、固定经某个中继、固定传输方式。

### 8.2 切换规则

| 情形 | 规则 |
|---|---|
| 发现更优路径 | 新路径得分优于当前至少 15% 且至少 10 毫秒，并持续 30 秒，才切换（防抖） |
| 当前路径故障 | 隧道内连续 3 次探测丢失（约 6 秒），或丢包率超过 30% 持续 3 秒：**立即**切换到次优路径 |
| 所有 UDP 路径不可用 | 改用 TLS 传输 |
| UDP 恢复 | 按"更优路径"规则切回 |

### 8.3 由谁决定

WireGuard 会根据最近一次通过认证的数据包的来源，自动更新对端的 endpoint（漫游机制）。如果双方各自选择路径，会相互覆盖。因此**每一对成员由一方决定路径**：

- 一方为 `dial-only`、另一方为 `public` 时，由 `dial-only` 一方决定；
- 否则由成员 ID 较小的一方决定；
- 另一方通过漫游机制自动跟随，不主动修改 endpoint。

### 8.4 Hub 离线

候选路径、中继分配和密钥都保存在本地；测量、评分和切换完全在成员本地完成。Hub 离线期间，无法新增候选路径或中继分配，已有的仍然可用。

## 9. 传输

| 传输 | 阶段 | 用途 |
|---|---|---|
| UDP | M2 | 默认 |
| TLS（WebSocket，443） | M2 | UDP 不可用时 |
| QUIC（UDP 443） | M5 | UDP 可用但端口受限或特征被识别时 |
| 混淆包装 | M5 | 视需要 |

## 10. 局域网智能入口

- 智能入口宣告一个或多个局域网网段；**宣告网段扩大了组网可访问的范围，属于高风险变更**（动作 `node.advertise_routes`，需签名）；
- 智能入口开启 IP 转发，对从组网进入局域网的流量做**源地址转换**：局域网主机看到的来源是智能入口的局域网地址，回包不会被本机的其他 VPN 或代理截走；
- 同一局域网中的其他成员可以发现彼此，优先走局域网直连；
- 网关设备自带的 WireGuard 可以作为备用路径：作为一个固定 endpoint 的普通对端接入，不参与自动选路。

## 11. 主机名

- 后缀默认 `nett.internal`（`.internal` 为保留给私有网络使用的顶级域），可在 Hub 初始化时修改；
- 每个节点自动获得 `<节点名>.nett.internal`；服务可以获得 `<服务名>.<节点名>.nett.internal`；用户可以添加别名（`hostnames` 资源）；
- nett-node 在组网地址上运行一个精简的 DNS 应答器，只回答该后缀下的名称；
- 本机解析配置：Linux 通过 systemd-resolved 为 `nett0` 设置该后缀的分域解析；macOS 写入 `/etc/resolver/<后缀>`；
- 设备：导出的 WireGuard 配置中，DNS 指向移动网关的组网地址；网关回答组网名称，其他查询转发给上游。

## 12. 访问控制

- **默认允许**：组网成员之间默认互通；`access-rules` 用于收窄；
- 规则编译为每个成员本地的过滤规则：Linux 使用 nftables，作用于 `nett0` 的入站方向，按来源组网地址、目的端口匹配；用户态实现由 nett-node 在转发前过滤；
- WireGuard 的 `AllowedIPs` 保证来源地址无法伪造；
- 规则变化属于高风险变更（见 changes.md）。

## 13. 手机与移动网关

- 移动网关是承担 `gateway` 角色的 `public` 节点：在 `nett0` 上接受设备作为对端，并把设备流量经路径层送入组网；
- 导出给设备的配置包含两个对端，按网段分流：

| 对端 | `AllowedIPs` |
|---|---|
| 家里的智能入口（直连） | 家里宣告的局域网网段，以及智能入口的组网地址 |
| 移动网关 | 组网网段中的其他部分 |

- 标准客户端无法在对端之间自动切换：直连不可用时，访问家里的流量不会自动改走网关。因此同时导出一份**"全部经网关"**的备用配置，供用户在直连受阻时手动切换；自建 App（M6）将自动处理；
- 设备之间的流量经移动网关转发。

## 14. 平台

| 平台 | 会话层 | 过滤 | 备注 |
|---|---|---|---|
| Linux（内核 ≥ 5.6） | 内核 WireGuard（netlink） | nftables | 主要目标 |
| Linux（旧内核）、Synology DSM | Rust 用户态实现 + TUN | 用户态 | DSM 需要 root 才能使用 TUN |
| macOS | Rust 用户态实现 + utun | 用户态 | 需要考虑与其他 VPN 应用共存 |
| 手机 | 标准 WireGuard 客户端 | 由移动网关和智能入口执行 | 见第 13 节 |

用户态 WireGuard 的具体实现在 M2 开工前评估选定。

## 15. 故障与降级

| 情形 | 行为 |
|---|---|
| 当前路径中断 | 约 6 秒内切换到次优路径 |
| 中继宕机 | 经该中继的连接切换到其他路径；Hub 恢复后重新分配 |
| 所有 UDP 不可用 | 切换到 TLS 传输 |
| Hub 离线 | 本地自主选路与切换；无法新增候选和分配 |
| 成员被移除 | Hub 下发新拓扑，其他成员删除其公钥，经它的中继分配作废 |
| 时钟偏差 | 不影响 WireGuard；影响测量时间戳，偏差过大时告警 |

## 16. 可观测性

- `links` 资源：每条连接的当前路径、传输、质量、候选得分、最近一次切换及原因；
- 指标：`link.rtt`、`link.loss`、`link.jitter`、`link.bytes`、`relay.bytes`；
- 事件：路径切换、传输切换、中继超限、候选全部不可用；
- `nett status` 显示本机各连接的当前路径；`nett doctor` 检查端口可达性、WireGuard 状态、DNS、过滤规则。
