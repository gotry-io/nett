# 组网

- 状态：草案
- 阶段：P0 设计；M2 实现第一版，M5 增强（见第 18 节）
- 相关：ADR [0007](../adr/0007-own-mesh-wireguard-session-path-layer.md)、[0008](../adr/0008-mobile-dual-path.md)、[0011](../adr/0011-nett-relay.md)、[0013](../adr/0013-datapath-process.md)、[0014](../adr/0014-signed-mesh-membership.md)、[0015](../adr/0015-origin-identity-and-lan-default-deny.md)、[0016](../adr/0016-macos-container-member.md)；[protocol.md](protocol.md)、[auth.md](auth.md)、[overview.md](overview.md)

## 1. 目标

节点之间有多条候选路径和多种传输方式；持续测量，自动选择最优路径；路径抖动、中断或节点离线时在几秒内切换，**进行中的连接不中断**；没有单点；Hub 离线不影响组网；**nett-node 停止也不影响已建立的路径**。

不在本期范围：每条连接独立选路（同一对节点的所有流量共用一条路径）；不同站点之间网段重叠的自动处理；Windows 平台；macOS 原生数据面（ADR 0016）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 成员 | 加入组网的节点或设备 |
| 连接（link） | 一对成员之间的 WireGuard 会话 |
| 候选路径 | 一条连接可能使用的路径：局域网直连、公网直连、经中继、多跳接力 |
| 传输 | 承载 WireGuard 数据包的方式：UDP、TLS（WebSocket）、后期的 QUIC |
| `public` / `dial-only` | 能否被外部连入（见 architecture.md 第 6.5 节） |
| 中继 | 运行 nett-relay、为其他成员转发密文的 `public` 节点 |
| 智能入口 | 把整个局域网段接入组网的节点 |
| 移动网关 | 接受设备连接、把设备流量送入组网的节点 |
| 数据面进程 | `nett datapath`：TLS 传输适配，以及用户态平台上的 WireGuard（ADR 0013） |
| 准入材料 | 证明一个对端可以加入组网的签名产物（第 4.1 节） |
| Edge 专用地址 | 入口节点上专供 Edge 发出流量使用的组网地址（ADR 0015） |
| 容器内成员 | 在宿主的 Docker Linux 虚拟机中运行的成员，用于 macOS（ADR 0016） |

## 3. 地址规划

| 地址 | 规则 |
|---|---|
| IPv4 组网网段 | 默认 `100.88.0.0/16`，在 Hub 初始化时可修改；避开部分云厂商在 `100.100.0.0/16` 上提供的内部服务 |
| IPv6 组网网段 | Hub 初始化时随机生成一个 ULA `/48` |
| 成员地址 | 每个节点一个 IPv4 和一个 IPv6 地址，在创建入网 token 时分配；设备的每份 WireGuard 凭据一对地址（同一设备的多份凭据会同时作为网关的不同对端，而 WireGuard 不允许对端的 `AllowedIPs` 重叠），在创建凭据时分配。地址写入签名产物，终身不变；移除后冻结 90 天再回收 |
| Edge 专用地址 | 每个开启 ingress 模块的节点额外一对地址，写入签名节点策略 |
| 局域网网段 | 由智能入口宣告（第 10 节） |

Hub 在分配地址和宣告网段时检测冲突，以下情况都会被拒绝并提示：组网网段与任何成员的局域网网段或上报的外网地址重叠（家宽运营商的 CGNAT 地址同样位于 `100.64.0.0/10`）；两个站点宣告的网段重叠；启用了 tailscale 后备，而它的地址池没有排除组网网段（ADR 0007）。

## 4. 会话层

- 每个节点一个 WireGuard 接口 `nett0`，监听一个 UDP 端口（默认 `41820`，可配置）；
- 对端：所有其他节点；设备只作为智能入口和移动网关的对端（第 13 节）；
- 每个对端的 `AllowedIPs`：它的组网地址；它的 Edge 专用地址（如有）；它宣告的局域网网段（如有）；以它为当前网关的设备地址（如有，仅限具有 `gateway` 角色的节点）；
- **WireGuard 私钥在本机生成，不离开节点**；公钥连同准入材料经 Hub 分发（期望状态的 `mesh` 分区）；
- Linux 使用内核 WireGuard，通过 netlink 配置；无内核模块的平台（Synology DSM、旧内核）使用 Rust 用户态实现与 TUN 设备，运行在数据面进程中；
- `dial-only` 成员对每个对端设置 25 秒的持久保活，维持 NAT 映射。

**切换路径 = 修改对端的 endpoint**。WireGuard 会话、密钥和上层的 TCP 连接都不受影响。nett-node 只负责计算和下发 endpoint；内核或数据面进程按最后一次的配置持续工作。

### 4.1 准入验证

成员只为能验证签名链条的对端配置 WireGuard（ADR 0014）：

| 对端属性 | 验证依据 |
|---|---|
| 节点的组网公钥和地址 | 信任锚 → 含 mesh 模块的签名节点策略（含节点 ID、地址、入网公钥）→ 准入证明（入网私钥对节点 ID、身份公钥、组网公钥的签名） |
| Edge 专用地址 | 签名节点策略中的 ingress 模块与地址分配 |
| 设备的组网公钥和地址 | `device.add` / `device_credential.create` 的签名产物 |
| 局域网网段 | `node.advertise_routes` 的签名产物 |
| 设备地址出现在某个节点对端上 | 该节点的签名策略具有 `gateway` 或智能入口角色 |
| 访问规则 | 整份规则集的签名产物，版本号只增不减 |

验证失败的对端不配置，并以事件上报。移除成员、撤销网段、收窄规则可以不带签名，直接生效。

## 5. 中继

### 5.1 转发模型

中继不参与 WireGuard 会话，只转发密文。**每个中继只使用一个 UDP 端口**，按 WireGuard 消息本身判断去向（ADR 0011）：

| 消息 | 中继怎样判断去向 |
|---|---|
| 握手发起（type 1） | `mac1` 以接收方公钥为密钥计算；中继用分配给它的连接中的公钥逐个试算，确定接收方 |
| 握手应答（type 2） | 同样用 `mac1` 确定接收方；记下双方的会话索引 |
| cookie 应答、数据（type 3、4） | 按接收方索引查表 |

```
A 的 WireGuard ──► R:p ──(按 mac1 / 会话索引)──► B 的 WireGuard
A 的 WireGuard ◄── R:p ◄─(按 mac1 / 会话索引)─── B 的 WireGuard
```

- 经 R 的连接中，A 把 B 的 endpoint 设为 `R:p`，B 把 A 的 endpoint 也设为 `R:p`；同一个中继可以同时是多个对端的 endpoint；
- R 记录每个成员的实际地址，把数据包转给另一端；
- **多跳**：R1 不直接转给 B，而是转给 R2，R2 同样按消息判断去向；
- 会话索引冲突时，中继丢弃冲突的握手，WireGuard 会自动以新索引重试；表项按会话的空闲时间老化。

### 5.2 分配与授权

- 哪些连接经过哪个中继由 Hub 计算，经期望状态下发给中继所在节点，nett-node 再通过本机接口通知 nett-relay；分配内容只包括两端的公钥和准入的连接，中继只为分配给它的连接转发；
- **地址绑定**：成员的实际地址只在**对端针对新地址上的握手发起发回了应答**之后才更新。`mac1` 只能证明发送者知道接收方的公钥，单独的握手发起可能是重放或伪造；而 WireGuard 会拒绝重放的握手，没有私钥也构造不出能被对端接受的握手，所以拿不到应答。中继不需要任何私钥；
- 每个中继的流量和带宽上限由用户在控制台为节点设置，经 Hub 下发；超过上限时，Hub 不再为它分配新的连接；
- 试算 `mac1` 的次数和索引表的大小都有上限。

### 5.3 TLS 传输

当 UDP 不可用时：

```
A 的 WireGuard ─► 127.0.0.1:x（数据面进程）─► WebSocket/TLS 443 ─► R 的 nett-relay ─► B
```

- 数据面进程在本机回环地址上开一个 UDP 端口作为 WireGuard 的 endpoint，把收到的数据包按长度前缀写入 WebSocket 连接，反方向同理；它只经手密文，在 Linux 上以低权限运行；
- 入口节点上，Edge 按域名把 WebSocket 反向代理给 nett-relay；
- 其他 `public` 节点上，nett-relay 直接在 443 上提供 TLS；证书可以是自签的，指纹由 Hub 随中继名单下发，客户端按指纹校验。节点没有可用域名时（例如所在地区要求域名在该云厂商备案），客户端按 IP 连接，不发送 SNI。这条传输和其他候选一样，是否可用由测量决定（第 7 节），被拦截时路径层自动不选，不需要预先测试；
- TLS 传输中，WireGuard 承载的 TCP 在丢包时性能会下降（TCP 套 TCP），因此只在 UDP 不可用时使用。

### 5.4 CONNECT 代理

- HTTP/2 over TLS，按连接转发，可以串联多个中继；
- 入口节点上与网站共用 443：Edge 按"方法为 CONNECT 且 TLS 的 SNI 为 nett-relay 的域名"转交，不能按 Host 转交（CONNECT 请求的 `:authority` 是目标地址）。实测标准 Caddy 2.10.2 能转发 HTTP/2 CONNECT 隧道，但不能转发 HTTP/1.1 CONNECT 隧道，因此入口节点上只提供 HTTP/2 CONNECT；其他 `public` 节点上的 nett-relay 两种都支持；
- 客户端凭据是设备凭据的一种（`kind = connect`，见 api-resources.md 第 5.7 节），新增需要签名；
- CONNECT 的出口使用中继节点上专用的组网地址，可访问的目标由签名的访问规则限定；
- Edge 所在主机本身是组网成员，回源直接走组网，不使用 CONNECT。

### 5.5 公网端口与安全组

nett 不能修改云厂商的安全组，而有的云厂商默认拒绝全部入方向 UDP。每种角色需要的端口如下，由用户在云控制台放行一次；`nett doctor` 和控制台检测到端口不通时，会说明应该放行哪个端口。

| 角色 | 协议与端口 | 用途 |
|---|---|---|
| 所有 `public` 节点 | UDP 41820（可配置） | WireGuard |
| 运行 nett-relay 的节点 | UDP 中继端口（一个，可配置） | 中继转发、探测应答 |
| | TCP 443 | TLS 传输入口、CONNECT；入口节点上与 Edge 共用 |
| 入口节点 | TCP 80、443 | 网站、证书验证 |
| 智能入口（家宽） | 路由器映射 WireGuard 端口和中继端口 | 设备直连家里；可做中继 |
| M5 | UDP 443 | QUIC 传输 |

可达性检测：WireGuard 端口对未认证的数据包不作响应，无法从外部直接探测，通过实际握手是否成功来判断；中继端口和 443 由其他 `public` 节点发起带认证的探测。

## 6. 候选路径

Hub 为每一对成员计算候选路径列表，经 `mesh` 分区下发；成员在本地测量并选择。

| 候选路径 | 生成条件 |
|---|---|
| 局域网直连 | 双方上报的局域网地址处于同一网段，且探测确认可达 |
| 公网直连 | 至少一方为 `public` |
| 经中继 | 选取若干中继：优先地理和线路上位于两端之间的中继，结合线路质量矩阵 |
| 多跳接力（M5） | 单跳中继质量不佳，而两段接力明显更优 |
| 打洞直连（M5） | 双方都为 `dial-only` |

每种路径还可以与传输方式组合（UDP、TLS）。候选数量有上限（默认每对成员 6 条）。`dial-only` 成员的候选中，至少包括经两个不同 `public` 节点的路径（architecture.md 第 12.3 节）。

**活跃连接**（最近 10 分钟有流量）完整测量；**空闲连接**只做低频测量，第一次有流量时立即按最优候选建立。

## 7. 测量

| 测量 | 方式 | 频率 |
|---|---|---|
| 当前路径 | 在隧道内发送探测（到对端组网地址），测往返时间和丢包 | 活跃连接每 2 秒 |
| 候选路径 | 隧道外的探测包，按路径分段测量：成员 → 中继、中继 → 成员、成员 → `public` 成员；经中继的路径由各段组合估算 | 活跃连接每 15 秒；空闲连接每 5 分钟 |
| 线路质量矩阵 | 汇总各段测量，上报 Hub | 每分钟 |

- 指标：往返时间（指数滑动平均）、丢包率（滑动窗口）、抖动；
- 探测包带认证：成员之间用双方 WireGuard 密钥派生的密钥计算校验码；发往中继的探测使用分配时下发的令牌；
- 应答方：`public` 节点上由 nett-relay 在中继端口上应答；隧道内的探测由 nett-node 在组网地址上应答；局域网直连的探测由 nett-node 在局域网地址上应答，**只在 Hub 判定存在局域网直连候选时开启**。云主机网卡上的"局域网地址"往往通过 1:1 NAT 对应公网地址，因此所有应答方**对未认证的探测都不作任何响应**；
- 探测流量有预算：每对活跃连接不超过约 1 KiB/s；
- M1 没有中继和组网，线路测量只由节点主动发起（ICMP、到已开放端口的 TCP 建连时间），由 metrics 模块作为普通指标上报，不新增任何监听。

## 8. 选路与切换

### 8.1 评分

```
得分 = 往返时间 + 丢包惩罚 + 抖动惩罚 + 路径类型偏好 + 传输惩罚 + 中继负载
```

- 路径类型偏好：局域网 < 公网直连 < 经中继 < 多跳；
- 传输惩罚：TLS 高于 UDP；
- 中继负载：中继接近用户为它设定的流量上限时提高。上限只是容量机制，nett 不关心机器如何计费、上层业务如何使用带宽；
- 支持策略覆盖（`links` 的 `spec.policy`）：优先直连、固定经某个中继、固定传输方式。

### 8.2 切换规则

| 情形 | 规则 |
|---|---|
| 发现更优路径 | 新路径得分优于当前至少 15% 且至少 10 毫秒，并持续 30 秒，才切换（防抖） |
| 当前路径故障 | 隧道内连续 3 次探测丢失（约 6 秒），或丢包率超过 30% 持续 3 秒：**立即**切换到次优路径 |
| 所有 UDP 路径不可用 | 改用 TLS 传输 |
| UDP 恢复 | 按"更优路径"规则切回 |

### 8.3 由谁决定

WireGuard 会根据最近一次通过认证的数据包的来源，自动更新对端的 endpoint（漫游机制）。如果双方各自选择路径，会相互覆盖。因此**每一对成员由一方决定路径**：

- 一方为 `dial-only`、另一方为 `public` 时，由 `dial-only` 一方决定；
- 否则由成员 ID 较小的一方决定；
- 另一方通过漫游机制自动跟随，不主动修改 endpoint。

### 8.4 Hub 或 nett-node 离线

候选路径、中继分配、准入材料和密钥都保存在本地；测量、评分和切换完全在成员本地完成。Hub 离线期间，无法新增候选路径或中继分配，已有的仍然可用。nett-node 停止期间，内核或数据面进程保持当前路径，但不再切换。

## 9. 传输

| 传输 | 阶段 | 用途 |
|---|---|---|
| UDP | M2 | 默认 |
| TLS（WebSocket，443） | M2 | UDP 不可用时；由数据面进程适配 |
| QUIC（UDP 443） | M5 | UDP 可用但端口受限或特征被识别时 |
| 混淆包装 | M5 | 视需要 |

## 10. 局域网智能入口

- 智能入口宣告一个或多个局域网网段；**宣告网段扩大了组网可访问的范围，属于高风险变更**（动作 `node.advertise_routes`，需签名，签名产物由其他成员验证）；
- 智能入口开启 IP 转发，对从组网进入局域网的流量做**源地址转换**，回包不会被局域网主机上的其他 VPN 或代理截走。智能入口在局域网中使用两个地址，**按来源分类转换**（ADR 0015）：

| 组网来源 | 转换为 | 局域网服务如何对待 |
|---|---|---|
| 某个入口节点的 Edge 专用地址 | 入口地址 | 需要真实 IP 的服务把它配置为可信代理，信任它发来的 `X-Forwarded-For` |
| 其他成员和设备 | 普通地址 | 不信任任何转发头 |

- 转换后的地址**绝不能是回环地址**；转发到某台主机上的服务时，使用该主机的局域网地址（macOS 的 Docker 中，经 `host.docker.internal` 到达宿主的流量，来源会变成 `127.0.0.1`）；
- 宣告网段默认拒绝访问（第 12 节）。宣告时，控制台提示："局域网中按来源网段信任的服务，会信任所有被放行的组网流量"；
- 同一局域网中的其他成员可以发现彼此，优先走局域网直连；
- 网关设备自带的 WireGuard 可以作为备用路径：作为一个固定 endpoint 的普通对端接入，不参与自动选路；
- 在 NAS 一类系统上，智能入口需要的 TUN、IP 转发和 NAT 能力要由能力探测逐项确认。

## 11. 主机名

- 后缀默认 `nett.internal`（`.internal` 为保留给私有网络使用的顶级域），可在 Hub 初始化时修改；
- 每个节点自动获得 `<节点名>.nett.internal`；服务可以获得 `<服务名>.<节点名>.nett.internal`；用户可以添加别名（`hostnames` 资源）；
- 节点没有开启 mesh 模块、位于已宣告的局域网段中时，它和它的服务的主机名解析为该节点的局域网地址；
- nett-node 只在组网地址上运行一个精简的 DNS 应答器，回答该后缀下的名称；
- **转发上游**：只有移动网关和智能入口为设备转发其他查询，只接受来自设备地址的查询，并限制速率，不成为开放的转发器；
- 本机解析配置：Linux 通过 systemd-resolved 为 `nett0` 设置该后缀的分域解析；macOS 写入 `/etc/resolver/<后缀>`；
- 设备：导出的 WireGuard 配置中列出两个 DNS 服务器，分别是移动网关和智能入口的组网地址；
- Edge 配置中写组网地址，不写主机名：Edge 常运行在容器中，容器默认使用宿主的上游 DNS，解析不了组网后缀。

## 12. 访问控制

- **成员之间默认允许**：节点和设备之间默认互通，`access-rules` 用于收窄；
- **宣告的局域网段默认拒绝**：只对用户的设备开放；其他成员需要显式规则；
- **Edge 专用地址**：只能访问路由指向的目标主机和端口，相应的规则由路由生成，随路由的变更一起签名；
- 规则集整体作为一份签名产物下发，版本号只增不减；新增 deny 规则、删除 allow 规则属于收窄，可以不签名直接生效；
- 规则编译为每个成员本地的过滤规则：Linux 使用 nftables，作用于 `nett0` 的入站方向（智能入口上还作用于转发方向），按来源组网地址、目的地址和端口匹配；用户态平台由数据面进程在转发前过滤；
- WireGuard 的 `AllowedIPs` 保证来源地址无法伪造。

## 13. 手机与移动网关

- 移动网关是承担 `gateway` 角色的 `public` 节点（角色由签名节点策略授予）：在 `nett0` 上接受设备作为对端，并把设备流量经路径层送入组网；
- 导出给设备的配置包含两个对端，按网段分流：

| 对端 | `AllowedIPs` |
|---|---|
| 家里的智能入口（直连） | 家里宣告的局域网网段，以及智能入口的组网地址 |
| 移动网关 | 组网网段中的其他部分 |

- **设备归属**：在 WireGuard 中，一个地址只能出现在一个对端的 `AllowedIPs` 里，因此同一时间一台设备只归属一个移动网关，由它代为宣告设备地址。部署多个移动网关时，设备的每份导出配置对应一个网关；网关上报设备的最近握手，Hub 据此把设备地址移到当前网关对端的 `AllowedIPs` 中（只能在具有 `gateway` 角色的节点之间移动，第 4.1 节）；
- 标准客户端无法在对端之间自动切换：直连不可用时，访问家里的流量不会自动改走网关。因此同时导出一份**"全部经网关"**的备用配置，供用户在直连受阻时手动切换（移动端 App 暂不计划）；
- 设备之间的流量经移动网关转发。

## 14. 平台

| 平台 | 会话层 | 过滤 | 备注 |
|---|---|---|---|
| Linux（内核 ≥ 5.6） | 内核 WireGuard（netlink） | nftables | 主要目标；TLS 传输由数据面进程适配 |
| Linux（旧内核）、Synology DSM | 数据面进程：Rust 用户态实现 + TUN | 数据面进程 | DSM 需要 root 才能使用 TUN |
| macOS | 容器内成员：Docker Linux 虚拟机中的内核 WireGuard（ADR 0016） | nftables（虚拟机内） | 宿主上的原生 nett-node 负责 metrics、deploy；原生 utun 方案推迟 |
| Home Assistant OS | 加载项内运行，使用 HAOS 内核自带的 WireGuard（ADR 0017） | 宿主网络上的包过滤（以能力探测为准） | 可做智能入口、移动网关、中继 |
| 手机 | 标准 WireGuard 客户端 | 由移动网关和智能入口执行 | 见第 13 节 |

用户态 WireGuard 的具体实现在 M2 开工前评估选定，M2 只需覆盖 DSM 和旧内核的 Linux。

## 15. 故障与降级

| 情形 | 行为 |
|---|---|
| 当前路径中断 | 约 6 秒内切换到次优路径 |
| 中继宕机 | 经该中继的连接切换到其他路径；Hub 恢复后重新分配 |
| 所有 UDP 不可用 | 切换到 TLS 传输 |
| Hub 离线 | 本地自主选路与切换；无法新增候选和分配 |
| nett-node 停止（升级、崩溃） | 保持当前路径，不再切换；node 恢复后继续 |
| 数据面进程停止 | 经它的路径（TLS 传输、用户态平台上的全部路径）中断，nett-node 带退避地重启它 |
| 成员被移除 | Hub 下发新拓扑，其他成员删除其公钥，经它的中继分配作废 |
| 准入材料验证失败 | 不配置该对端，上报事件 |
| 时钟偏差 | 不影响 WireGuard；影响测量时间戳，偏差过大时告警 |

## 16. 可观测性

- `links` 资源：每条连接的当前路径、传输、质量、候选得分、最近一次切换及原因；
- 指标：`link.rtt`、`link.loss`、`link.jitter`、`link.bytes`、`relay.bytes`；
- 事件：路径切换、传输切换、中继超限、候选全部不可用、准入材料验证失败；
- `nett status` 显示本机各连接的当前路径；`nett doctor` 检查端口可达性（按第 5.5 节的清单给出需要放行的端口）、WireGuard 状态、DNS、过滤规则。

## 17. 资源预算

| 项 | 上限 |
|---|---|
| 每对成员的候选路径 | 6 条 |
| 探测流量 | 每对活跃连接约 1 KiB/s |
| nett-node 的组网状态内存（含准入材料） | 50 个成员规模下不超过 1 MiB |
