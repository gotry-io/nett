# 路线图

每个阶段都**单独可用**。每个阶段开工前，先在 [design/](design/README.md) 中写好该阶段的设计文档。

```
P0 立项 → M1 观测 → M2 组网 → M3 部署与入口 → M4 MCP 与 AI 运维 → M5 自研传输与 agent 通信 → M6 移动端 App
```

## P0：立项

- [x] 愿景、架构、路线图、架构决策记录
- [ ] 设计：API 资源模型
- [ ] 设计：认证与授权
- [ ] 设计：变更集与动作目录
- [ ] 设计：node ↔ Hub 协议
- [ ] Rust workspace 与 Web 骨架、CI（clippy、测试、cargo-deny、生成文件检查）、发布签名

## M1：观测

- Hub 与 nett-node：入网、能力探测、资产清单、主机和容器指标、平台特有指标；node 经公网 HTTPS 连接 Hub，不依赖组网
- 认证：passkey 登录、API token、node 密钥
- 告警：阈值、OOM 与重启、节点离线、心跳缺失、趋势预测
- Web 控制台：节点、服务、指标、告警
- 完整的 OpenAPI；`nett doctor`；排障手册

**验收**：在 1 vCPU / 1 GB 的机器上，node 空闲 24 小时内存 ≤ 5 MB；Hub ≤ 30–50 MB 且 24 小时浸泡测试内存不上涨；30 天图表查询 < 200 ms；心跳缺失能触发告警。

## M2：组网

- tailscale 后端（由 Hub 管理，对上层隐藏）；subnet router 接入局域网段
- 节点身份与身份查询 API、服务注册表、主机名解析
- 移动网关、设备与凭据模型、客户端配置导出（WireGuard 二维码、代理工具配置）
- 每条链路的路径数据采集

**验收**：Edge 回源全部经过组网；手机可以访问内网服务。

## M3：部署与入口

- Git 期望状态、CI（OIDC）触发、版本可见、回滚、部署钩子
- ingress 模块：路由 → Edge 配置；回源健康与证书监测
- 变更集 API；浏览器内 passkey 签名授权
- 暴露面审计、只读日志
- 从现有工具导入 stack 和路由

**验收**：CI 推送后自动部署并可一键回滚；路由在控制台配置后自动生效。

## M4：MCP 与 AI 运维

- MCP 适配层
- 运维 Agent：告警 → 诊断 → 提案 → 审批 → 执行 → 验证；初期所有动作都需要审批

## M5：自研传输与 agent 通信

- 内核 WireGuard 后端，按 M2 采集的数据逐个节点切换
- 网关级接入局域网段
- 私有传输（QUIC、TLS），先用于服务器之间受限的链路
- 工作负载身份、MCP 网关

## M6：移动端 App

- 控制台：状态、告警推送、审批、签名
- 隧道：WireGuard + 私有传输，自动切换
