# 路线图

每个阶段都**单独可用**。每个阶段开工前，先在 [design/](design/README.md) 中写好该阶段的设计文档。

```
P0 立项 → M1 观测 → M2 组网 → M3 部署与入口 → M4 MCP 与 AI 运维 → M5 组网增强与 agent 通信 → M6 移动端 App
```

- [ ] 设计：API 资源模型
- [ ] 设计：认证与授权

## M1：观测

- Hub 与 nett-node：入网、能力探测、资产清单、主机和容器指标、平台特有指标；node 经公网 HTTPS 连接 Hub，不依赖组网
- **线路测量**：节点之间、节点到关键目标的延迟、丢包、抖动，形成线路质量矩阵，为 M2 选路积累数据
- 认证：passkey 登录、API token、node 密钥
- 告警：阈值、OOM 与重启、节点离线、心跳缺失、趋势预测
- Web 控制台：节点、服务、指标、线路质量、告警
- 完整的 OpenAPI；`nett status`、`nett doctor`、`nett leave`；排障手册
- 安装：Hub 安装脚本与一次性初始化；节点一键入网（安装脚本与签名发布包由 Hub 分发）；Homebrew；自动升级与回滚
- 可用性：node 本地缓存配置和指标；Hub 外部死信开关；Hub 备份与重建手册

**验收**：

- 在 1 vCPU / 1 GB 的机器上，node 空闲 24 小时内存 ≤ 5 MB；Hub ≤ 30–50 MB 且 24 小时浸泡测试内存不上涨；30 天图表查询 < 200 ms；心跳缺失能触发告警；
- 停止 Hub 一段时间：node 继续运行，Hub 恢复后指标补传完整；
- 停止 Hub 后，外部死信开关能发出告警；
- 按手册在另一台主机上从备份重建 Hub，所有 node 自动重新连接。

## M2：组网

- 会话层：Linux 内核 WireGuard；无内核模块的平台使用 Rust 用户态实现
- 路径层：局域网直连、公网直连、经单个中继；持续测量、打分、防抖、快速切换；节点离线时自主切换
- 传输：UDP；TCP/TLS 443 兜底
- nett-relay：转发加密数据包、接收 TCP/TLS 传输、探测应答、HTTPS CONNECT 代理
- 局域网智能入口（subnet router + 源地址转换）
- 节点身份与身份查询 API、服务注册表、主机名解析、访问控制
- 手机：移动网关 + 直连家里的双路径；设备与凭据模型；导出标准 WireGuard 配置（配置文件和二维码）
- Web 控制台：拓扑图，每对节点的当前路径、传输方式、延迟、丢包
- 可用性：至少两个可用中继（位于不同主机）；`dial-only` 节点至少连接两个 `public` 节点

**验收**：

- Edge 回源全部经过组网；手机在外可直连家里观看视频，也可经移动网关访问其他节点；
- 人为制造丢包或断开当前路径：几秒内切换到其他路径，**进行中的 TCP 连接不中断**；
- 停掉任一中继或节点：依赖它的路径自动绕开；
- 屏蔽 UDP：自动改用 TCP/TLS 443；
- 停止 Hub：组网、自动切换和手机接入照常工作；
- 每个节点上 nett-node 与 nett-relay 的空闲内存合计仍满足资源预算。

## M3：部署与入口

- Git 期望状态、CI（OIDC）触发、版本可见、回滚、部署钩子
- ingress 模块：路由 → Edge 配置；回源健康与证书监测
- 变更集 API；浏览器内 passkey 签名授权
- 暴露面审计、只读日志
- 从现有工具导入 stack 和路由

**验收**：CI 推送后自动部署并可一键回滚；路由在控制台配置后自动生效。

## M4：MCP 与 AI 运维

- MCP 适配层
- 运维 Agent：告警 → 诊断 → 提案 → 审批 → 执行 → 验证；初期所有动作都需要审批

## M5：组网增强与 agent 通信

- 多跳接力与自动寻路
- QUIC 传输、混淆包装、CONNECT 的 UDP 支持
- 打洞直连（两端都在 NAT 后的场景）
- 工作负载身份、MCP 网关

## M6：移动端 App

- 控制台：状态、告警推送、审批、签名
- 隧道：内置路径层，自动选路和切换传输
