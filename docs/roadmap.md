# 路线图

每个阶段都**单独可用**。每个阶段开工前，先在 [design/](design/README.md) 中写好该阶段的设计文档。

```
P0 立项 → M1 观测 → M2 组网 → M3 部署与入口 → M4 MCP 与 AI 运维 → M5 组网增强与 agent 互访
```

移动端 App 暂不计划：Web 控制台承担全部查看、管理、审批和签名；手机通过标准 WireGuard 客户端接入组网。

## M1：观测

- Hub 与 nett-node（原生运行）：入网、能力探测、资产清单（机器、服务、对外监听的端口）；以替代轻量监控（如 Beszel）为准的指标：主机 CPU、内存、磁盘、网络、温度，容器指标，平台特有指标（如 NAS 的 SMART、RAID）；原生服务的观测（进程、systemd 服务与定时器）；node 经公网 HTTPS 连接 Hub，不依赖组网。首批平台：Linux、Synology DSM、macOS、Home Assistant OS（加载项，指标经 Supervisor 接口读取）
- **线路测量**：节点之间、节点到关键目标的延迟、丢包、抖动，形成线路质量矩阵，为 M2 选路积累数据（由节点主动发起，不新增监听）
- 认证：passkey 登录、恢复密钥与备份密钥、API token、node 密钥与准入证明、信任锚；变更集最小版本与浏览器内 passkey 签名
- 告警：阈值、OOM 与重启、节点离线、心跳缺失（URL 心跳，以及 systemd 定时器没有按时成功）；渠道为 Telegram、邮件、webhook
- Web 控制台：节点、服务、指标与历史图表、线路质量、告警；中英双语
- 完整的 OpenAPI；`nett status`、`nett doctor`、`nett leave`，命令行输出中英双语；排障手册（中英双语）
- 安装：Hub 安装脚本与一次性初始化，生成 Hub 主机的初始 Edge 配置；节点一键入网（安装脚本与签名发布包由 Hub 分发）；Homebrew；Home Assistant 加载项仓库；自动升级与回滚（项目发布签名、防降级）
- 可用性：node 本地缓存配置和指标；Hub 外部死信开关；Hub 备份（含身份私钥，加密后由其他节点拉取）与重建手册

**验收**：

- 在 1 vCPU / 1 GB 的机器上，node 空闲 24 小时内存 ≤ 5 MB；Hub ≤ 30–50 MB 且 24 小时浸泡测试内存不上涨；30 天图表查询 < 200 ms；心跳缺失能触发告警；
- 停止 Hub 一段时间：node 继续运行，Hub 恢复后指标补传完整（在本地缓冲上限之内，见 protocol.md 第 7 节）；
- 停止 Hub 后，外部死信开关能发出告警；
- 按手册在另一台主机上从备份重建 Hub，所有 node 自动重新连接。使用的备份要落后于节点的状态（备份之后又批准过变更），恢复后不需要用户重新批准（protocol.md 第 6.4 节）。

## M2：组网

- **原型关卡**（M2 第一步，只在 Linux 上）：签名准入、UDP 中继与切换到新中继、双方都是 `dial-only` 时的切换与时间片汇合、漫游纠正、中继重启、MTU（大包 TCP）、TLS 回退，以及所选 WireGuard 实现的实际行为（索引冲突重试、删除再添加对端后的握手时间）。实测的切换时间达到下面的验收标准后，再做其他平台、CONNECT 和智能入口（mesh.md 第 18 节）
- 组网进程独立于 nett-node 运行，TLS 传输适配单独以低权限运行（ADR 0013）
- 会话层：Linux 内核 WireGuard；DSM 和旧内核使用 Rust 用户态实现，运行在组网进程中；macOS 以容器内成员加入；Home Assistant OS 加载项可做智能入口；成员准入验证（签名的成员表、网段、访问规则）
- 路径层：局域网直连、公网直连、经单个中继；持续测量、打分、防抖、快速切换；节点离线时自主切换
- 传输：UDP；TCP/TLS 443 兜底（由传输适配进程适配）
- nett-relay：单端口转发加密数据包、接收 TCP/TLS 传输、探测应答、HTTPS CONNECT 代理（入口节点上仅 HTTP/2）
- 局域网智能入口（subnet router + 按来源分类的源地址转换）；Edge 专用地址；宣告网段默认拒绝
- 节点身份与身份查询接口（`whois`）、服务注册表（`services` 与 `hostnames`）、主机名解析、访问控制
- 手机：移动网关 + 直连家里的双路径；设备与凭据模型；导出标准 WireGuard 配置（配置文件和二维码）
- Web 控制台：拓扑图，每对节点的当前路径、传输方式、延迟、丢包
- 可用性：至少两个可用中继（位于不同主机）；`dial-only` 节点至少连接两个 `public` 节点

**验收**：

- Edge 回源全部经过组网（ingress 模块在 M3，本阶段手工修改 Edge 配置），需要真实 IP 的服务能识别访客地址；手机在外可直连家里观看视频，也可经移动网关访问其他节点；切换到"全部经网关"的备用配置后，仍能访问家里的服务；
- 人为制造丢包或断开当前路径：几秒内切换到其他路径，**进行中的 TCP 连接不中断**；切换到此前没有经手这条连接的中继，以及中继重启后，同样满足；大包传输不受影响；
- 停掉任一中继或节点：依赖它的路径自动绕开；
- 屏蔽 UDP：自动改用 TCP/TLS 443；
- 停止 Hub：组网、自动切换和手机接入照常工作；
- 停止 nett-node：组网照常测量和切换，DNS 照常应答；
- Hub 下发一个没有准入材料的对端：所有成员都拒绝配置它；移除一个成员后，Hub 重发它原来的准入材料：所有成员都拒绝；一个很久以前入网的成员，新加入的成员能正常验证它；
- 每个节点上 nett-node、组网进程、传输适配进程、nett-relay 的空闲内存各自满足资源预算。

## M3：部署与入口

- 容器部署（Compose）：CI（如 GitHub Actions）构建镜像后经 OIDC 通知 Hub 有新版本；控制台显示可升级的版本和差异，**默认手动一键部署**，每个 stack 可以单独开启自动部署；部署钩子（在容器中运行）；健康检查失败自动回滚；一键回滚到之前的版本。原生服务只观测，不部署
- ingress 模块：路由 → Edge 配置；回源健康与证书监测；路由的回源选项（真实 IP）与入口节点的域名约束
- 变更集补全：多步骤、影响分析、自动执行策略、主动验证与回滚
- 部署档位；机密用节点公钥加密下发，并绑定签名的 stack 定义（除镜像版本外的改动需要签名）
- 只读的容器日志
- 外部对接：CI 身份首批为 GitHub Actions；证书验证用的 DNS 服务商首批为阿里云 DNS、Cloudflare
- 从现有工具导入 stack 和路由

**验收**：

- CI 构建出新版本后，控制台显示可升级；一键部署成功，健康检查失败时自动回滚，并可一键回滚到上一版本；开启自动部署的 stack 无需操作即完成部署；
- 路由在控制台配置后自动生效；Hub 下发一个没有签名的回源目标（包括与 Edge 同机的服务）：ingress 模块拒绝生成配置；
- 原有的容器管理面板和反向代理管理界面可以下线，日常操作不再需要 SSH 登录机器。

## M4：MCP 与 AI 运维

- MCP 适配层
- 运维 Agent：告警 → 诊断 → 提案 → 审批 → 执行 → 验证；初期所有动作都需要审批

## M5：组网增强与 agent 互访

本阶段的内容都是必须做的，不是视情况再定。

- 多跳接力与自动寻路
- QUIC 传输、混淆包装、CONNECT 的 UDP 支持
- 打洞直连（两端都在 NAT 后的场景）
- agent 互访：工作负载身份（细化到每个 agent 或容器）、服务发现、MCP 网关（工具级授权与调用审计）

**验收**：

- 人为劣化单跳中继：两段接力明显更优时自动改走多跳，连接不中断；
- 只放行 UDP 443 的网络中自动改用 QUIC；在按 WireGuard 特征丢包的模拟环境中，混淆传输仍能连通；
- 两端都在常见类型的 NAT 后：打洞直连成功，失败时自动回落到中继；
- 两台机器上的 agent 经组网互相调用，被调用方能验证调用者的工作负载身份；MCP 网关拒绝未授权的工具调用，并为每次调用留下审计记录；
- 每个节点上的常驻进程仍满足资源预算。
