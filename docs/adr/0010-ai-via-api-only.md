# 0010. AI 只经由 Hub API 接入，node 不含 AI 逻辑

- 状态：已采纳
- 日期：2026-10-12

## 背景

项目定位为 AI Native：AI 应当能理解系统状态并参与运维，同时系统可以作为 AI agent 之间通信的基础设施。AI 的输出不可完全信任：它可能出错，也可能受到日志等数据中的提示词注入影响。

## 决定

- AI 只通过 Hub 的对外 API 接入（以后由 MCP 适配层包装）；node 中永远不运行 AI 逻辑；
- 现阶段不实现 AI 功能，而是把基础设计好：资源模型、API 优先、变更集（plan → approve → apply → verify）、带风险等级的动作目录、身份模型、审计事件；
- 以后的运维 Agent 作为 Hub 侧的独立服务运行：只能从动作目录中选择操作，输出只是提案，由策略引擎按风险分级，高风险操作必须由用户签名（见 ADR 0006）；
- 不提供 shell 或任意命令执行。

## 理由

- 人和 AI 走同一条变更路径，安全机制只需要建设一次；
- node 保持小巧、行为确定，便于验证资源占用和安全性；
- 只要 API 完善，加入 MCP 只是一层很薄的适配。

## 放弃的方案

- **现在就实现 MCP 和运维 Agent**：在 API 尚未稳定时，适配层会反复返工。
- **允许 AI 执行命令**：能力强，但无法约束和审计。

## 影响

- API 设计必须覆盖界面的全部能力，并且对每个操作标注风险等级。
