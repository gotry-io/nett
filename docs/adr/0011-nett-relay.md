# 0011. nett-relay：独立的低权限中继与传输入口

- 状态：已采纳
- 日期：2026-10-12；2026-11-04 修订（单端口中继、地址绑定规则、与 Edge 共用 443 的方式、CONNECT 凭据；外部评审后改正地址绑定的安全论证，CONNECT 由中继逐连接授权）

## 背景

自研组网（ADR 0007）需要中继转发、TCP/TLS 等传输入口和路径探测应答，这些都要求监听公网端口。按 ADR 0001，高权限的 nett-node 不能监听公网端口。

另一类需求是"由应用自己发起 TCP 连接"：客户端在 UDP 受限的网络里访问内网服务。这类客户端不便运行组网，但普遍支持 HTTPS 代理。（Edge 所在主机本身是组网成员，回源直接走组网，不需要 CONNECT。）

## 决定

新增独立进程 **nett-relay**，以低权限运行在 `public` 节点上：

| 功能 | 说明 |
|---|---|
| 数据包中继 | 转发 WireGuard 加密后的数据包，看不到内容。**每个中继只使用一个 UDP 端口**，按 WireGuard 消息本身判断去向（见下） |
| 传输入口 | 接收 TCP/TLS 443 传输（后期加入 QUIC），把数据包交给本机的 WireGuard |
| 探测应答 | 响应路径层的测量探测；对未认证的探测不作响应 |
| **HTTPS CONNECT 代理** | HTTP/2 over TLS；按连接转发；可串联多个中继；凭据为设备凭据的一种（见 auth.md） |

**单端口中继**：握手发起和握手应答中的 `mac1` 以接收方公钥为密钥计算，中继逐个试算已知公钥即可确定接收方。转发握手发起时先记下发起方的会话索引和来源（待定表项），cookie 应答可以据此送回；收到握手应答后记下双方的会话索引；之后的数据消息按接收方索引转发。中继不需要任何私钥。

**地址绑定**：`mac1` 只能证明发送者知道接收方的公钥。中继收到来自新地址的握手发起时先不改绑定，**对端针对这次握手发回应答后**，才把绑定改到新地址；握手应答只接受来自对端当前绑定地址的。中继没有密钥，验证不了应答的真假：能伪造来源地址的攻击者仍可能伪造应答、改掉绑定。后果是这条连接的密文被送往错误的地址，也就是断线，内容不会泄露。因此另加两条：绑定变化限速；新绑定后一段时间内收不到来自新地址的数据，就恢复旧绑定。路径层发现中断后照常切换。

**与 Edge 共用 443**（实测标准 Caddy 2.10.2）：

| 流量 | Edge 怎么转交 | 结果 |
|---|---|---|
| 网站 | 按 Host | 正常 |
| WebSocket 传输 | 按 Host 反向代理给 nett-relay | 正常 |
| HTTP/2 CONNECT | 请求的 `:authority` 是 CONNECT 的目标，不能按 Host 路由；改为匹配"方法为 CONNECT 且 TLS 的 SNI 为 nett-relay 的域名" | 隧道正常，TLS 套在隧道内也正常；其他 SNI 不会被放行 |
| HTTP/1.1 CONNECT | 同上 | 请求能到达 nett-relay，但 Caddy 把应答当作普通响应处理，隧道建立不起来 |

因此，入口节点的 443 上只提供 HTTP/2 CONNECT。只支持 HTTP/1.1 CONNECT 的客户端，使用非入口节点上直接监听 443 的 nett-relay。

**TLS 证书**：入口节点上由 Edge 终止 TLS；其他节点上 nett-relay 自己提供 TLS，证书可以是自签的，指纹由 Hub 随中继名单下发，客户端按指纹校验。节点没有可用域名时（例如所在地区要求域名在该云厂商备案），客户端直接按 IP 连接，不发送 SNI。

**中继之间每一跳都使用 TLS**；实际使用哪些中继、CONNECT 走哪条路径，由 Hub 根据线路质量决定。

## 理由

- 保持"有权限的不对外，对外的没权限"：即使 nett-relay 被攻破，攻击者也拿不到组网私钥，无法管理节点；
- 单端口让每个中继在安全组里只需要放行一个 UDP 端口，只映射了一个端口的节点（如家里的智能入口）也能做中继；
- HTTPS CONNECT 是通用标准，支持 HTTPS 代理的客户端都能直接使用，不需要专用客户端；
- 数据包中继和 CONNECT 共用 TLS、认证和选路基础设施，放在同一个进程里实现成本最低。

## 放弃的方案

- **在 nett-node 中实现中继**：少一个进程，但违反 ADR 0001。
- **每条经中继的连接分配两个端口（类似 TURN）**：实现简单，但要在安全组里放行一大段端口，只映射了一个端口的节点无法做中继。
- **CONNECT 使用独立端口**：不受 Edge 的能力限制，但受限网络往往只放行 443。实测表明 HTTP/2 CONNECT 可以与网站共用 443，因此不需要独立端口。
- **只提供数据包中继**：只支持 HTTPS 代理的客户端无法直接使用。
- **只提供 CONNECT**：只支持 TCP，无法承载任意协议的组网流量。

## 影响

- CONNECT 只支持 TCP；UDP 支持（如 CONNECT-UDP）放到后期；
- CONNECT 中继能看到目的地址，非加密流量的内容也可见。中继都运行在用户自己的机器上，可以接受；
- CONNECT 的出口使用专用的组网地址，所有设备共用；目标节点据此区分不了设备，因此由 nett-relay 按凭据逐连接检查签名的访问规则，并在系统层面限制它只能经组网以这个地址发起连接，不能访问本机和本地局域网（mesh.md 第 5.4 节）；
- 单端口中继要处理会话索引冲突和表项老化，试算 `mac1` 的开销要有上限；切换到一个尚未经手某条连接的中继时，需要重新握手才能建立索引（mesh.md 第 8.4 节）；
- nett-relay 自己持久化最后一次的中继分配，重启时不依赖 nett-node（ADR 0013）；
- 非入口节点上的 nett-relay 绑定 443，需要 `CAP_NET_BIND_SERVICE`；
- `public` 节点上多一个进程，空闲内存计入资源预算。
