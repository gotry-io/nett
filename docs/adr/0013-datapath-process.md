# 0013. 组网数据面独立于 nett-node

- 状态：已采纳
- 日期：2026-11-04

## 背景

组网设计中有两处要在用户态处理数据包：UDP 不可用时的 TLS 传输适配器，以及无内核模块平台（Synology DSM、旧内核、macOS 原生）上的用户态 WireGuard。原设计把它们放在 nett-node 里，这与两条已有原则冲突：

- ADR 0001：nett-node 不处理业务流量；WireGuard 的 UDP 端口"由内核监听"，所以不算 nett-node 监听公网端口。用户态平台上，这个豁免的前提不成立；
- architecture.md 第 2 节：Hub 和 node 都停止时，组网照常工作。如果数据面在 node 里，node 每次升级或崩溃，走 TLS 传输的路径和用户态平台上的全部路径都会中断。而家里的智能入口恰好常用这类平台。

## 决定

新增**数据面进程** `nett datapath`。它是 `nett` 可执行文件的一个子命令（ADR 0012），由 nett-node 启停，作为独立的系统服务运行。

| 平台 | 数据面进程负责 | 运行身份 | 持有的密钥 |
|---|---|---|---|
| Linux（内核 WireGuard） | TLS 传输适配：在回环地址上收发 WireGuard 密文，转写到 TLS 连接 | 专用低权限用户 | 无，只经手密文 |
| 用户态平台 | 用户态 WireGuard + TUN + TLS 传输适配 | 能创建 TUN 的身份（这些平台上通常是 root） | 组网私钥 |

- nett-node 只计算和下发配置（对端、endpoint、传输方式、过滤规则），经本机接口交给数据面进程；数据面进程按最后收到的配置持续工作，不依赖 node 在线；
- 用户态平台上，组网私钥由 nett-node 生成，经权限为 `0600` 的本机接口交给数据面进程，仍然不离开节点；
- 数据面进程不连接 Hub、不解析 Hub 的消息、不执行任何外部命令；
- 用户态 WireGuard 与内核实现一样，对未认证的数据包不作任何响应；
- 资源预算单独计算：空闲 RSS ≤ 5 MB，转发缓冲有上限。

## 理由

- 恢复"管理和流量分离"：node 升级、崩溃或重启时，已建立的路径不中断；
- 恢复"有权限的不对外"：node 不在任何公网端口上处理数据包；
- Linux 上的传输适配只经手密文，可以用低权限运行，被攻破也拿不到明文。

## 放弃的方案

- **保留在 nett-node 中**：少一个进程，但两条原则都要降级成"仅内核 WireGuard 的 UDP 路径不受影响"，而智能入口正是受影响最大的节点。
- **放进 nett-relay**：relay 只在 `public` 节点上运行，而且按设计不持有组网私钥。

## 影响

- 节点上多一个系统服务，资源预算表增加一行；
- nett-node 与数据面进程之间需要一个本机接口（配置下发、状态与计数上报），接口有版本号，与 node 一起升级；
- 数据面进程本身升级时，经它的路径会短暂中断。它的变化频率远低于 node，可以单独安排升级。
