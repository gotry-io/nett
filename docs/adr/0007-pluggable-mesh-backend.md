# 0007. 可替换的组网后端：先 tailscale，后内核 WireGuard

- 状态：已采纳
- 日期：2026-10-12

## 背景

内核 WireGuard 内存占用约为零、性能最好，但它只是一条加密隧道：不负责密钥分发、地址分配、对端发现、NAT 穿透和 TCP 兜底。tailscaled 提供这些能力，但它是常驻的 Go 进程，空闲 25–70 MB，跑流量时可能涨到 200 MB 以上。

在部署之前，很多网络情况是未知的：跨境链路的 UDP 是否被限速或识别、NAT 型 VPS 是否转发 UDP、局域网网关是否支持站点互联。

## 决定

- 组网抽象为可替换的后端（`MeshBackend`）。上层只看到 nett 的概念：节点、地址、主机名、访问规则、链路状态；
- **第一个后端是 tailscale**：Headscale + derper + tailscaled，由 Hub 部署和管理，对上层隐藏；
- 运行期间采集每条链路的路径数据（直连还是中继、延迟）；
- **第二个后端是内核 WireGuard**：依据数据逐个节点切换。

约定：上层（例如 Edge 回源）只使用主机名，不使用 IP；Hub 的数据模型不保存后端特有的概念；两个后端沿用同一套地址规划。

## 理由

- tailscale 后端能吸收大部分未知因素（自带 NAT 穿透和 TCP 443 兜底），让项目不被网络问题卡住；
- 它同时是一个测量工具：直连稳定的链路，换成内核 WireGuard 也能工作；
- 在常见拓扑中（每条链路至少一端有公网地址），内核 WireGuard 不需要打洞，需要自行补齐的能力（密钥与地址分发、endpoint 更新、主机名、ACL、健康监测）难度不高。

## 放弃的方案

- **一开始就用内核 WireGuard**：资源最优，但在未知网络条件下风险大。
- **永久使用 tailscaled**：省事，但无法满足资源约束。
- **其他组网方案**（NetBird、ZeroTier、Nebula、EasyTier 等）：分别存在服务端资源要求高、许可证限制、缺少 iOS 客户端或无法嵌入等问题。EasyTier 的多传输设计是私有传输的参考。

## 影响

- 第一阶段每个直接入网的节点多出 tailscaled 的内存开销；
- 需要维护 Headscale 和 derper，直到切换完成；
- UDP 受限的链路，最终由私有传输（QUIC、TLS，按连接转发）解决。
