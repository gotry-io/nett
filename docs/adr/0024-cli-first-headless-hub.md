# 0024. 命令行是操作界面，Hub 先不带控制台

- 状态：已采纳
- 日期：2026-11-10

## 背景

本地签名部署（ADR 0022）中，用户在自己的电脑上用 `nett site` 定义并签名整张网，再把每台机器的期望状态手工拷过去。机器多起来以后，手工步骤（复制公钥、拷文件、每次 `sudo`、逐台升级）成为主要的负担，而这些步骤的根源是用户的电脑与各台机器之间没有通道，各台机器上也没有常驻的代理接收东西，与有没有图形界面无关。

在 M1 里同时完成 Hub、nett-node、Web 控制台、passkey 登录与签名、变更集（ADR 0005、0006，changes.md）时，控制台、passkey 与变更集是工作量最大的部分。另外，在控制台里签名有一个已知的薄弱点：签名载荷由 Hub 提供的页面计算，被攻破的 Hub 可以让页面显示一项操作、实际请求签名另一项（auth.md 第 2 节）。

## 决定

- **命令行是操作界面**：定义网络、签名、查看全部机器的状态、邀请新机器，都用 `nett` 完成。签名照旧在用户自己的电脑上进行，由签名工具在本机计算并显示要签的内容；
- **站点用命令维护**（参考 ufw）：机器、Edge 与宣告的网段、访问规则都由 `nett site` 的命令增删，每条命令列出要签名的内容，确认后签名并送达；哪些机器之间建立连接由访问规则推导；站点状态由工具保存，没有手工编辑的文件。接不接 Hub 用同一套命令（design/site.md）；
- **Hub 是常驻的服务端，没有界面**：保存签名产物和站点模型，为每台机器组成期望状态，经节点网关下发，汇总各台机器的状态，以后还负责升级与运行时协调。Hub 不持有任何能签名的钥匙；
- **每台机器上的 nett-node** 连接 Hub，接收期望状态并交给组网进程，上报状态；
- **入网命令由签名工具生成**，写明发布包的哈希（签名工具先核对发布签名），节点下载发布包、核对哈希之后再运行；安装不运行 Hub 提供的脚本；
- **Web 控制台、passkey 登录与签名、变更集推迟**：需要时作为同一套 API 上的另一个前端加入，不改变 Hub 与节点之间的协议和签名格式；
- 不接 Hub 的站点照常使用本地签名部署（local-signing.md）。

设计见 design/hub.md 与 design/site.md。

## 理由

- 消除手工步骤的是"常驻的服务端 + 每台机器上的代理"这条通道。先把通道做出来，就得到了自动分发、一条命令入网、集中查看状态；
- 签名在用户自己的电脑上、由不依赖 Hub 的工具计算和显示内容，Hub 被攻破时无法诱导用户签下别的东西，比在 Hub 提供的页面里签名更安全。入网命令也由这个工具生成并带上发布包的哈希，被攻破的 Hub 发不出带后门的安装程序，"Hub 被攻破不能越权"因此没有附加的前提。vision 中"可以有"的"独立于 Hub 的批准工具"由此成为主要的路径；
- 单用户、几台到十几台机器的规模下，命令行足以完成全部操作；
- 站点由工具保存、规则按机器 ID 记录：移除一台机器时，引用它的规则一起清理，同名的新机器不会继承；以后的控制台和多台签名设备修改的也是同一份数据。站点中的访问规则只有放行、没有顺序，一条一条地增删不会因为位置出错：iptables 要整份文件管理、ufw 可以用命令管理，区别就在这里；
- 推迟的部分不是过渡代码之外的另一套东西：控制台以后建在同一套 API 上，节点协议与签名格式不变。

## 放弃的方案

- **先做控制台**：工作量最大的部分放在最前，很久之后才能替代手工步骤；签名的内容依赖 Hub 的页面；
- **命令行经组网直连每台机器**（不要服务端）：用户的电脑必须在线才能分发、升级、协调；管理通道走组网，组网配置出错时可能一起断掉（违背硬性规则 8）；多台签名设备的状态会分叉；
- **不做 Hub**：机器少时手工分发可以接受，但入网、升级、地址变化、中继调度和集中查看都无法自动完成；
- **手工编辑的站点描述文件**（TOML）：加一台机器要先编辑文件；规则按名字引用机器，机器移除之后规则留在文件里，同名的新机器会继承；以后的控制台改不了用户电脑上的文件；
- **逐对指定连接**：机器多了要写很多对；访问默认拒绝，没有规则放行的一对即使连上也传不了数据。

## 影响

- vision.md 中 Web 控制台与 passkey 属于"可以有"，roadmap 中 Web 控制台未排期；architecture.md 第 4、5、13.3 节按 design/hub.md 描述 Hub、认证与安装，第 11 节有站点模型的库 `nett-site`，第 13.4 节中整张网的命令见 design/site.md；local-signing.md 的站点由命令维护；
- auth.md：初始化经 `nett site link` 完成（第 4.1 节），入网 token 由签名工具生成（第 8 节），站点持有 `owner` token（第 6 节）；登录、会话与 passkey 随 Web 控制台加入（第 13 节）；
- ADR 0005、0006、0008、0012 的状态注明推迟或修改的部分（0012：安装脚本不由 Hub 提供）；changes.md、api-resources.md 中控制台与变更集的部分随 Web 控制台加入；
- 签名钥匙在这一阶段只有恢复密钥，保存在用户的电脑上（ADR 0022 的风险不变）；以后的改进是硬件密钥或多台设备各自的钥匙（design/hub.md 第 9 节）；
- 手机的配置（ADR 0008）由命令行生成配置文件与二维码。
