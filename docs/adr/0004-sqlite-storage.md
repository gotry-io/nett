# 0004. Hub 使用 SQLite 存储，包括指标

- 状态：已采纳
- 日期：2026-10-12

## 背景

Hub 需要保存期望状态、身份、审计和指标。目标规模是单用户、数个到数十个节点。

## 决定

- 使用 SQLite（WAL 模式），通过 sqlx 访问；
- 指标存放在同一个数据库，按固定粒度分层降采样，最多保留 30 天（例如 1 分钟粒度保留 1 小时，逐级到 480 分钟粒度保留 30 天），超过保留期的数据删除，总行数趋于稳定。

## 理由

- 无需额外的数据库进程，部署仍然是单一二进制；
- sqlx 在编译期检查 SQL，能拦截一类常见错误；
- 在目标规模下，分层降采样后的指标量很小，SQLite 足以支撑。

## 放弃的方案

- 独立的关系数据库：多一个进程和运维负担。
- 专用时序数据库：功能强，但资源占用和运维成本与目标规模不匹配。

## 影响

- 需要显式限制 SQLite 的缓存和 mmap；
- 如果将来规模显著扩大，可以把指标迁移到专用存储，而不影响其余数据。
