# 架构

本文描述整体架构和长期稳定的设计原则。各阶段的详细设计见 [design/](design/README.md)，关键决策的理由见 [adr/](adr/README.md)。

## 1. 总览

```
┌──────────────────────────── 浏览器 ─────────────────────────────┐
│ Web 控制台：React SPA，WebAuthn（passkey 登录与签名）             │
└───────────────┬────────────────────────────────────────────────┘
                │ HTTPS：REST/JSON + SSE
┌───────────────▼──────────── Hub 主机（同时是入口节点）────────────┐
│ Edge：反向代理（TLS 终止）                                        │
│ nett-hub：对外 API · 认证 · 期望状态 · 变更集 · 告警 · 审计          │
│           SQLite · node 网关 · 内嵌 Web 前端                          │
│ nett-relay：中继与公网传输入口（低权限）                              │
│ nett-node                                                       │
└───────────────┬────────────────────────────────────────────────┘
                │ 控制：WebSocket over TLS + Protobuf（node 主动连接）
                │ 数据：nett 组网（WireGuard 会话 + nett 路径层）
        ┌───────┼────────────┬─────────────────┐
     VPS 节点   VPS 节点     家里的智能入口      家里的其他主机
     nett-node（+ nett-relay）                 （经智能入口接入，无需安装）

外部：CI ─OIDC─► Hub　　手机 ─标准 WireGuard─► 家里入口 / 移动网关
```

## 2. 角色与能力边界

| 角色 | 负责 | 不负责 | 权限 | 监听公网 |
|---|---|---|---|---|
| **Hub** | 保存期望状态；汇总状态和指标；告警；对外 API；分发组网拓扑；转发签过名的策略 | 直接操作机器；自行提升任何节点的权限；处于数据通路上 | 普通 | 经 Edge 暴露 |
| **nett-node** | 在本机执行：组网（WireGuard 会话、路径选择）、采集、部署、生成 Edge 配置；上报状态 | 监听公网端口；执行任意命令；运行 AI 逻辑；自行决定权限 | 高 | 否 |
| **nett-relay** | 中继转发加密数据包；接收 TCP/TLS 等传输；探测应答；按连接转发（CONNECT） | 解密组网流量；任何管理功能 | 低 | 是 |
| **Edge** | TLS 终止；按域名把请求转发到组网内的服务 | 任何管理功能 | 低 | 是 |
| **用户的 passkey** | 签名批准提升权限的变更 | — | 持有签名私钥 | — |

**三条原则**

1. **管理和流量分离**：Hub 和 node 都停止时，网站和组网照常工作，只是暂时无法变更和观测。
2. **有权限的不对外，对外的没权限**：nett-node 永远不监听公网地址（只在局域网和组网地址上提供探测应答和 DNS）；所有公网监听都交给独立的低权限进程（Edge、nett-relay，以后的 MCP 网关）。WireGuard 的 UDP 端口由内核监听，对未认证的数据包不作任何响应。
3. **决定和执行分离，提升权限必须签名**：Hub 被攻破也无法越权。

## 3. nett-node

单进程，tokio 单线程运行时，由以下部分组成：

- **Transport**：主动连接 Hub，认证，断线重连，多端点选优；
- **Supervisor**：计算模块是否生效，管理模块生命周期，崩溃后带退避地重启；
- **四个模块**：每个都是调和器（期望状态 → 实际状态 → 差异 → 执行），可重复执行，相互隔离；
- **State Store**：本地保存身份密钥、上一次生效的配置、组网拓扑和部署版本。**启动时先应用本地缓存，再连接 Hub**，避免组网和 Hub 相互依赖。

| 模块 | 负责 | 典型启用位置 |
|---|---|---|
| **metrics** | 主机和容器指标；平台特有指标（如 NAS 的 RAID、SMART、卷使用率）；节点间线路质量 | 所有节点 |
| **deploy** | 按 stack 定义拉镜像、启动、回滚，执行部署钩子；上报服务与端口 | 运行容器的节点 |
| **mesh** | WireGuard 会话管理与路径层（见第 6 节）；上报链路状态 | 直接加入组网的节点 |
| **ingress** | 把 Hub 的路由翻译成 Edge 配置并推送；检查回源健康和证书 | 入口节点 |

### 模块开关

**生效 = 本地未禁止 ∩ 节点能力 ∩ 签名策略**

| 层 | 由谁决定 | 作用 |
|---|---|---|
| 本地硬性禁止 | 节点管理员 | 可选的绝对上限，签名策略也无法突破 |
| 节点能力 | node 自动探测 | 缺少内核模块、Docker、root 权限等时，对应模块不可用或改用替代实现 |
| 签名策略 | Hub 下发 | 降低权限可直接下发；**提升权限必须带用户签名**；版本号只增不减 |

### 零配置

节点本地只保存**身份和权限**，其余来自 Hub 下发或本地探测：Hub 端点列表（入网时只需一个公网地址，其余由 Hub 推送，node 并发探测并选择最优）、网络可达性（`public` / `dial-only`）、局域网地址、组网地址、Docker socket 位置、平台特有采集项等。组网私钥在本机生成，永不离开节点。

```bash
curl -fsSL https://hub.example.com/install.sh | sh -s -- enroll <token>
```

## 4. Hub

- **对外 API**：REST + JSON，资源化；从代码生成 OpenAPI 3.1；Web、脚本、以后的 MCP 和移动端都使用同一套 API；
- **实时数据**：SSE；
- **node 网关**：WebSocket + Protobuf；
- **组网控制**：分配地址、分发公钥和候选路径、维护中继名单和线路质量矩阵；
- **存储**：SQLite（WAL）；指标分层降采样，最多保留 30 天；
- **告警**：阈值、OOM 与重启、节点离线、心跳缺失、趋势预测。

**资源保护**：所有队列、缓存和通道设置上限；查询图表时服务端降采样（每条曲线约 1000 个点）；限制 SSE 连接数；数据和审计有保留策略；上线前做 24 小时浸泡测试。前端运行在浏览器中，对 Hub 只增加约 1 MB 二进制体积。

## 5. 认证与授权

| 身份 | 认证方式 |
|---|---|
| 用户 | passkey（WebAuthn）+ 恢复码；短期会话 Cookie |
| API token | 带权限范围、有过期时间、可吊销；固定前缀；服务端只存哈希 |
| node | 一次性入网 token → X25519 身份密钥；连接时在 WebSocket 内层用 Noise 协议双向认证并端到端加密 |
| CI | OIDC（如 GitHub Actions），不保存长期密钥 |
| 手机设备 | 设备凭据（WireGuard 密钥） |

```
请求 → 识别身份 → 检查权限范围 → 检查策略 → 执行 → 写入审计
```

**token 只能提议高风险变更，不能批准。**批准由用户用 passkey 签名：把变更内容的哈希作为 WebAuthn 挑战，浏览器里即可完成。

## 6. 组网

### 6.1 目标

像导航软件一样工作：节点之间有多条候选路径和多种传输方式，持续测量，自动选择最优路径；路径抖动、中断，或某个节点离线时，在几秒内自动切换，**正在进行的连接不中断**；没有单点。

### 6.2 分层

```
┌─ 会话层：WireGuard（负责加密）────────────────────────────────┐
│ 每对节点一个加密会话；更换路径时会话不变                           │
│ Linux 使用内核 WireGuard；无内核模块的平台使用 Rust 用户态实现       │
├─ 传输层：可插拔（负责把加密包送达）──────────────────────────────┤
│ UDP（默认）· TCP/TLS 443 · QUIC 443（后期）· 混淆包装（后期）       │
├─ 路径层：nett-node mesh 模块（负责选路）─────────────────────────┤
│ 候选路径：局域网直连 · 公网直连 · 经中继 · 多跳接力                   │
│ 持续测量 → 打分 → 选择最优（带防抖）→ 变差时快速切换                  │
└──────────────────────────────────────────────────────────────┘
控制面：Hub（地址、公钥、候选路径、中继名单、线路质量矩阵）
```

- **会话层只用 WireGuard**：代码精简，经过形式化验证，Linux 内核原生支持，所有平台都有标准客户端。WireGuard 支持对端更换地址（为漫游设计），因此切换路径只需更新会话的对端地址，上层连接不受影响。
- **传输层可插拔**：WireGuard 只支持 UDP，特征也明显。UDP 受限时，把加密后的数据包放进 TCP/TLS 或 QUIC 传输，外部看到的是普通的 HTTPS 或 HTTP/3 流量。
- **路径层是 nett 的核心**：它决定每对节点之间走哪条路径、用哪种传输。

### 6.3 候选路径与选路

| 候选路径 | 条件 |
|---|---|
| 局域网直连 | 两个节点在同一局域网（由 Hub 下发双方的局域网地址，node 探测确认） |
| 公网直连 | 至少一端可从外部连入（`public`） |
| 经中继 | 经某个 `public` 节点的 nett-relay 转发 |
| 多跳接力 | 经两个或更多中继（如跨境时经优质线路） |
| 打洞直连（后期） | 两端都在 NAT 后；由 Hub 交换双方地址后同时发包 |

选路：

- 对每条候选路径持续测量延迟、丢包和抖动；
- 按得分选择当前路径；新路径需要**明显更好并持续一段时间**才切换，避免来回跳动；
- 当前路径连续丢包时**立即**切换到次优路径，不等待评分周期；
- 节点按本地缓存的拓扑自主切换，**不依赖 Hub 在线**；
- 支持策略覆盖，例如指定某类流量优先直连，或强制经某个中继。

### 6.4 中继

- **所有 `public` 节点都具备中继能力**（`dial-only` 节点和手机不能为其他节点中转）。Hub 根据位置、实测质量、流量配额和资源余量决定实际使用哪些中继。
- **中继只转发加密后的数据包，看不到内容**，端到端加密不受影响。
- 中继由独立的低权限进程 nett-relay 承担，只在转发流量时消耗资源。
- 在入口节点上，nett-relay 的 TCP 443 入口经 Edge 按域名转交，与网站共用 443 端口。

### 6.5 网络可达性

| 类型 | 含义 | 连接规则 |
|---|---|---|
| `public` | 可从外部连入（公网地址，或映射了端口） | 可以接受连接，可以做中继 |
| `dial-only` | 只能主动连出 | 主动连接 `public` 节点；**至少连接两个**，避免单点 |

可达性由 node 与 Hub 共同探测，网络变化后自动更新。

### 6.6 局域网接入

一个局域网只需要一台主机运行 nett-node，作为**智能入口**（subnet router）：把整个局域网段接入组网，并具备完整的选路和切换能力。局域网内的其他主机无需安装任何组网软件。智能入口对转发进来的流量做源地址转换，避免局域网主机的回包被本机的其他 VPN 或代理截走。网关设备自带的 WireGuard 可以作为备用路径。

### 6.7 按连接转发（CONNECT）

除了数据包级别的组网，nett-relay 还提供 **HTTPS CONNECT 代理**（HTTP/2 over TLS）：

- 适合"由应用自己发起 TCP 连接"的场景：支持 HTTPS 代理的程序访问内网服务，Edge 回源；
- 不需要专用客户端，任何支持 HTTPS 代理的程序都能使用；
- 只支持 TCP；中继能看到目的地址，非加密流量的内容也可见。中继都运行在用户自己的机器上，且中继之间每一跳都使用 TLS。

两种方式互补：组网承载任意协议；CONNECT 适合不便运行组网的客户端和应用层代理。

### 6.8 后备方案

tailscale（Headscale + derper + tailscaled）作为可选后备：在自研组网尚未覆盖的场景下使用，由 Hub 统一管理，对上层隐藏。上层只看到 nett 自己的概念（节点、地址、主机名、访问规则、链路状态）。

## 7. 手机接入

手机端兼容**任意标准 WireGuard 客户端**：nett 仅导出标准配置（配置文件与二维码），不限定客户端。配置包含**两条路径**：

```
手机 ─┬─ 直连家里的智能入口（标准 WireGuard）→ 家里的服务，大流量（如视频）不绕路
      └─ 移动网关（标准 WireGuard）→ 其他节点；直连不可用时兜底
```

- 两个对端按网段分流，标准客户端即支持；
- 移动网关是 Hub 主机（或其他 `public` 节点）上的 WireGuard 接口，网关之后的路径由 nett 路径层负责；
- 一台设备可以有多份凭据（第三方客户端一份、自建 App 一份），各自独立吊销，权限按设备授予；
- UDP 受限时，支持 HTTPS 代理的客户端可以经 nett-relay 的 CONNECT 代理访问内网服务；
- 以后的自建 App 内置路径层，在手机上也能自动选路和切换传输。

## 8. 入口路由

```
Hub 路由（域名 → 服务 → 节点:端口）→ ingress 模块 → Edge 配置
```

Hub 只保存与实现无关的路由模型；Edge 可以从 Caddy 换成其他反向代理，只需新增一个翻译后端。Edge 回源使用组网内的主机名，由路径层选择最优路径。

## 9. AI 接入

| 阶段 | 内容 |
|---|---|
| 现在 | 把基础打好：资源模型、API 优先、变更集（plan → approve → apply → verify）、动作目录（带风险等级）、身份模型、审计事件 |
| 以后 | MCP 适配层；运维 Agent（告警 → 诊断 → 提案 → 审批 → 执行 → 验证，作为 Hub 侧的独立服务）；agent 通信（工作负载身份、MCP 网关） |

AI 不能执行 shell；它的输出只是提案，必须经过策略引擎和签名。

## 12. 故障与可用性

### 12.1 Hub 与 node 的关系

Hub 是控制面，node 是执行者：

- node 主动连接 Hub，Hub 从不主动连接 node；
- node 只执行 Hub 下发的、签过名的期望状态，不自行决定权限；
- **node 在本地缓存上一次生效的配置和组网拓扑**，重启时先应用缓存，再连接 Hub；
- **Hub 不在数据通路上**：节点之间的组网流量、访客访问服务的流量都不经过 Hub；路径切换由节点自主完成。

### 12.2 故障场景

| 场景 | 继续工作 | 暂停 | 应对 |
|---|---|---|---|
| **Hub 进程停止**（崩溃、升级、重启） | 节点间组网与自动切换、Edge 回源、手机接入、已部署的服务 | 告警、部署与配置变更、新节点入网 | node 本地缓存指标（有上限），Hub 恢复后补传 |
| **Hub 主机宕机** | 不经过该主机的路径和服务 | 上述全部，以及该主机上的 Edge、中继、移动网关 | 路径层自动绕开；见 12.3 |
| **某个节点宕机** | 其余节点；以它为中继的路径自动绕开 | 该节点上的服务 | Hub 发出节点离线告警 |
| **某条路径变差或中断** | — | — | 路径层在几秒内切换，连接不中断 |

### 12.3 消除单点

1. **多点连接**：`dial-only` 节点至少连接两个 `public` 节点。
2. **至少两个可用中继**，且位于不同主机。这是冗余下限，不限制中继数量。
3. **组网不依赖控制面在线**：拓扑和密钥持久化在各节点本地，没有过期问题；Hub 不在时，节点照常选路和切换。
4. **移动网关可以部署多个**；手机同时保留直连家里的路径。
5. **外部死信开关**：Hub 定期向外部发送心跳，心跳中断即报警，解决"Hub 自己挂了谁来告警"的问题。实现方式可以是另一台节点上的极小监视程序，或外部的心跳检测服务。
6. **备份与重建**：Hub 的 SQLite 定期备份到其他主机；提供在另一台主机上重建 Hub 的操作手册。node 的端点列表包含备用入口，Hub 迁移后节点自动连上新的 Hub。

## 13. 打包、安装与运行

### 13.1 发布物

| 发布物 | 包含 | 安装位置 |
|---|---|---|
| **`nett`** | 一个可执行文件，按子命令运行为不同角色：命令行、`nett node`、`nett relay` | 所有节点 |
| **`nett-hub`** | Hub 与内嵌的 Web 前端 | 只在 Hub 主机 |

代码层面 node、relay、cli 仍是独立的 crate，最终链接成同一个可执行文件。这样安装和升级只有一次、版本不会错配；多个进程映射同一个文件，代码页由系统共享，总内存更低。安全隔离依靠运行用户和权限，与是否同一个文件无关。

### 13.2 运行方式

| 服务 | 运行身份 | 何时运行 |
|---|---|---|
| `nett-node` | root，或具备 `CAP_NET_ADMIN` 和 docker 组权限的用户 | 所有节点 |
| `nett-relay` | 专用的低权限用户；不持有组网私钥 | 由 Hub 按节点可达性和签名策略决定启用，nett-node 负责启停；`dial-only` 节点不运行 |
| `nett-hub` | 专用的低权限用户 | Hub 主机 |

服务管理：Linux 使用 systemd（设置内存上限），macOS 使用 launchd，Synology DSM 使用开机任务（以后提供套件包）。

### 13.3 安装

**Hub（一次）**

```bash
curl -fsSL https://<项目主页>/install.sh | sudo sh -s -- hub --domain hub.example.com
```

脚本下载并校验发布签名，安装服务，然后在终端打印**一次性初始化链接**；在浏览器中打开它注册 passkey 并保存恢复码。初始化链接只能使用一次，防止他人抢先完成注册。Hub 也提供容器镜像。

**节点**：在控制台"添加节点"并勾选模块，复制生成的命令：

```bash
curl -fsSL https://hub.example.com/install.sh | sudo sh -s -- enroll <一次性 token>
```

- **安装脚本和二进制都由用户自己的 Hub 提供**：脚本中预置 Hub 的公钥指纹；Hub 缓存经过签名的发布包，节点无需访问公共代码托管平台（在网络受限的地区更可靠）；
- token 一次性有效且很快过期；
- 不使用 `curl | sh` 时，可手动下载、校验签名后执行 `sudo nett enroll <token>`；
- macOS 也可以通过 Homebrew 安装后执行 `sudo nett enroll <token>`。

**手机**：无需安装 nett。控制台"添加设备"（passkey 确认）后导出标准 WireGuard 配置，用任意 WireGuard 客户端导入。

### 13.4 日常命令

| 命令 | 作用 |
|---|---|
| `nett status` | 本机状态：模块、Hub 连接、组网当前路径 |
| `nett doctor` | 自动诊断，给出通俗的说明和处理建议 |
| `nett upgrade` | 手动升级；默认由 Hub 统一推送，校验签名后替换，失败自动回滚 |
| `nett leave` | 退出组网并卸载，通知 Hub 吊销该节点凭据 |
